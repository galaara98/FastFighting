# FastFighting Core: developer notes

For anyone writing a system helper, another module that works with FastFighting, or changes to the core. [README.md](README.md) covers what GMs and players see; this file covers the API, the architecture, how the engine models a fight, and development.

## Architecture

FastFighting is split into a pure simulation engine, system **helpers**, and the Foundry UI. The core owns only its own ideas: personality, morale, leadership, positioning, standoffs, the story, and how creatures leave a fight. Every game rule comes from the helper. FastFighting PF2e, FastFighting D&D 5e and FastFighting DCC are reference implementations of three very different systems.

- `scripts/engine/`: the simulation, pure (no Foundry globals). `simulator.js` runs a BattleSpec against a rules object, and `batch-pool.js` runs the planner's batches on background workers (`batch-worker.js`: **The planner's fights on background workers** below); `battle-state.js` defines the CombatantSpec and per-run state; `live.js` keeps a run going a turn at a time for a live battle, `changes.js` turns one turn into a change set a helper writes onto the sheet, and `table-rolls.js` records the dice a live battle shows (see **Table rolls**). `behavior/` has one file per behavior (talk, standoff, neutral, morale, leaving, goad, traps, theft, doors, holds, troubles, summons, responses and the rest).
- `scripts/adapters/`: `adapter-base.js`, the SystemAdapter contract, and the experimental generic adapter.
- `scripts/foundry/`: the Foundry side. `battle.js` turns the scene and the GM's plan into a BattleSpec; `live-battle.js` plays a live battle on the tracker (`startLiveBattle` with `begin: false` prepares it, and `beginEncounter` begins it with the encounter, Foundry's Begin Encounter included); `auto-config.js` sets characters up; `pathing.js` and `terrain.js` read walls, regions and senses from the scene.
- `scripts/apps/`: the Battle Planner, the Battle Vantage (`battle-network.js` is its map of minds), the player survey, the token's FastFighting tab, and the settings menus.
- `scripts/story/`: the story in three styles, its tables, damage families, log lines and health callouts (**Health callouts** below).
- `scripts/core-api.js`: the stable surface helpers import. `scripts/api.js`: the runtime API.
- Words: `languages/en.json` and `story/en.json`; biography keywords in `keywords/`.

### Where things are kept

- **The plan** (per-battle options, side settings, per-token overrides, groups and fudges): a `fast-fighting.setup` flag on the encounter the planner is tied to, so it ends with the encounter; with no encounter, on the scene (`foundry/persistence.js`).
- **A character's answers:** actor flag `fast-fighting.tactics.<key>`, one field per answer, so two players sharing a token can edit different questions at once. Also `playstyles`, `stayTrue`, `roleplay` and `avoidCostlySpells` (`foundry/tactics.js`); an older `offer` or `expect` is dropped when read. What it worked out by itself: `flags.fast-fighting.auto` (`foundry/auto-config.js`).
- **Friendly Team votes:** on each player's User (`flags.fast-fighting.party`, `foundry/party.js`); survey status in the User flag `fast-fighting.survey`. The Friendly Team's roles from earlier fights: the hidden world setting `partyCommand`, by actor.
- **The planner's last runs:** in the GM's own browser, never in the world where players could read the odds (but the very last one while troubleshooting: **Live battles' journals** below); the newest 5 plans (`foundry/run-memory.js`). Each plan is its encounter's, by its uuid; `hasRun` says whether the planner has run an encounter, which the tracker's Vantage button needs.
- **Live battles:** a journal entry for each battle, only GMs see it, written a turn at a time (`foundry/live-keeping.js`); the last 12 turns keep the run as it was before them, for Rewind (`REWIND_DEPTH` in `foundry/live-battle.js`). See **Live battles' journals** below.
- **The combat's flag** (`flags.fast-fighting.live`, `flagOf`): `{id, active, user, inUse}`, read by every browser. `inUse`: begun, or the GM has used the Battle Vantage on it (`markInUse`: any action but `LOOKS`, or a changed input). A player's tracker hides Previous Turn while it's on and in use (`playersTracker`, the `ff-live-tracker` class); an encounter never flagged is Foundry's own. The tracker taken back to round 0 (Foundry tells no turn change for it) is put back (`onUnstarted`), but for Rewind This Encounter's own update (its options carry `MODULE_ID`).
- **The whole-fight playback of 0.1 to 0.2.5** kept undo records on the scene (flags `fast-fighting.undo` and `playback`) and its summary cards (`undoFight`, `concession`). They're no longer read: an old world may still hold them, harmlessly.

### Live battles' journals

`foundry/live-store.js` decides (pure, tested in `tests/live-store.test.js`); `foundry/live-journals.js` finds, makes and deletes; `apps/live-data.js` is the GM's **Live battle data** menu.
- **Transcripts:** each battle has a journal of its own, `FF_FF_LiveBattle_Transcript_<n>`, `n` the tracker's encounter number as the battle began (`encounterNumber`, 1 for a scene's only encounter). The number repeats across scenes and over time, so a taken name gets `_2`, `_3` and so on. All live in the folder `FF_FF_LiveBattle_Transcripts`, ownership None. These names are identifiers, never translated. Flags: `liveBattle` (the combat's id), `encounter` (n), `keptAt` (ms, written with every keep), and the battle in live-keeping.js's parts (`battles`, `specs`, `turns`, `snaps`, `logs`, each by combat id). A battle's transcript is found by its flags (its combat, and the battle's own id, `battles.<combat>.id`), never by its name.
- **Trust:** a journal holds a battle only while it's flagged, last changed by a GM, and no player has Limited or more (`distrustOf`). Otherwise a new one is made, and the old one stays, listed in Live battle data with why.
- **The Troubleshooting setting** (world, off by default) says how long they last (`whatGoes`):
  - Off: a transcript goes when its combat is deleted; and on the active GM's login, any whose combat is gone.
  - On: transcripts outlive their combat. On the active GM's login, those last kept more than 30 days ago (`KEEP_DAYS`) go, never one still in play on a combat that's there; the GM is told if any went. The planner's last run is kept too, in `FF_FF_BattlePlan_LastRun` (flag `planRun`, same folder and trust), replaced after each run: `ranAt`, `scene`, `encounter`, `holder`, `setup` (the plan with its options), `spec`, `results`, `seed`, `sample` (`{seed, log}`), `stopped` and `context` (as an export's). That puts the odds in the world, where a player who digs into what their browser was sent could read them; nothing is written while it's off, and a failure only warns in the console.
  - Either way, Rewind This Encounter deletes that battle's transcript, and only what's trusted goes by itself.
- **Clean up** (Live battle data): every journal of FastFighting's last kept more than 30 days ago (`keptAt`, else `_stats.modifiedTime`), whatever it is and whether trusted or not, but never one holding a battle still in play on a combat that's there. It shows what goes and what's held back, asks, deletes, and tells the GM.
- **Export** (Live battle data, one journal or all; nothing changes): `fastfighting-live-battles-<world>-<yyyy-mm-dd>.json`, a single journal's name after the date:
  ```
  {format: "fastfighting-live-battles", version: 1,
   context: {at, world, foundry: {version, generation, build}, system: {id, version}, modules: [{id, version}], coreApi,
             combats: {<combat id>: still there?}},
   journals: [{id, name, kind, trusted, distrust, createdTime, modifiedTime, createdBy, lastModifiedBy, lastKept, size, flags}]}
  ```
  `kind` is transcript or plan; `flags` is the module's flags on it, whole; `modules` lists every active FastFighting module, the core and its helpers.

### Settings

`scripts/settings.js` registers them. The settings window shows FastFighting's in groups, in `SETTING_GROUPS`' order (`live`, `story`, `planner`, `behavior`, `luck`, `after`, `troubleshooting`, `generic`), each a fieldset under its heading, `FASTFIGHTING.Settings.Group.<id>` (`groupSettings`, from main.js's `renderSettingsConfig`). Foundry has no groups of its own and lists a module's menus before its settings; the grouping puts each where it belongs.
- **A new setting** is a row of `SETTINGS` naming its `group`, placed in that group's block where it should show: a group shows its settings in the table's order, then its menus. Its words are `FASTFIGHTING.Settings.<key>.Name` and `.Hint`, and README's settings table gives it a row under its group. A new menu is a row of `MENUS` the same way, its window passed to `registerSettings`. A hidden setting (`config: false`) is registered on its own and needs no group.
- **A new group** goes in `SETTING_GROUPS` where it should show, with its heading in `languages/en.json` and its own table in README.
- **The system's own:** `SYSTEM_SETTINGS` lists the core settings a helper may make its system's (Max rounds, Lore-Collector advantage). `systemDefaults` (main.js, ready) applies the helper's `settingDefaults()`: a number's range (within the bounds) and default, a checkbox's or a list's default, and its own name and hint. `rangeOf(key)` reads a number's back for plans, the fight and the planner's slider. A value the GM set stands, held to the range.
- **A helper's own settings** (registered under its module id) show at the foot of FastFighting's tab under the helper's name (`helperGroup`, its tab's button hidden). **Systems without a helper** goes when the system has one.
- **The groups' look:** each is a `details` section, as in the planner (`groupSection`: its name and how many settings it holds); which are open is kept in the browser (`localStorage` `fast-fighting.settingsOpen`; at first only the helper's). The window's search opens them all while it has text (`openForSearch`).
- **Keys never change:** a stored value is found by its key alone, so a setting can move to another group, or along one, and keep its value.
- `tests/settings-groups.test.js` checks that every setting and menu the window shows is in exactly one group, the groups' order, and their headings.

### The Battle Planner's window

`apps/battle-planner.js`, three parts (`templates/planner/`): `topbar`, `left` and `right` (`details.hbs` is the right's Details tab). A view or tab change draws only its part (`render({ parts })`); anything that changes the plan draws all three.
- **Its own state** (not the plan's): `leftView` (teams, encounter, players), `sideFilter`, `rosterFilter` (filtered in the DOM as typed, `#filterRoster`, no drawing), `expandedTeams`, `detail` (`{kind: "team", key}` or `{kind: "creature", id}`; the Friendly Team at first), `resultTab` ("details" or a result's; "overview" at first), `openSections` (each `details[data-section]`, its `toggle` caught on the way down) and `previousResults` (each Overview number's change since the last run).
- **The Overview** (`#overview`) reads the aggregator's `party` (with `pCostlyWin` and `worstDowned`), `money` (`gained`, `lost`, in the smallest coin, from each fight's summary: a unit's `gave` and its end `worth`; shown in `mainCoin`; and `pDeal`), each friendly combatant's `pWinIfDowned` and `pWinIfUp` (`#linchpin`: the biggest gap, from enough fights either way), `foesEnd` (`FOE_ENDS`), `pFoeHeadFalls`, `pBystandersJoin` and `pReinforced` (engine/aggregate.js), each null where there's nothing to count, and the PCs' resources spent (`#partySpent`). A run kept from before these has none of them: its numbers just show no change.
- **Teams:** by group key (`commandGroup`'s, `PURSE_TEAMS`' and `options.reinforcements`'), shown as `TEAM_SHORT` (constants.js: F, H1 to H3, N1 to N3, Secret's S) in its color (`--ff-t-*`). A token's card is its chosen side's group (`#teamKey`); a Secret token's is the Secret card, its team the one picked (`#fightsFor`). Side settings stay by side, so a side's teams share them (Details says so).
- **Menus** (role, team, a creature's ⋯, the top bar's ⋯) are `popover` elements opened by their button's `popovertarget`, placed beside it and closed after an action (`apps/menus.js`). Escape is the `closeMenu` keybinding (PRIORITY, main.js), since Foundry's own Escape closes the window; Foundry's tooltip is a popover too, so it shows over them.
- **The top bar's buttons** come from `#actions`: Run, Stop, Go Live, and the one beside it held back (`aria-disabled`, saying why) while the plan has changed since its run or the helper can't play live.
- Controls that aren't the plan's (the filter, the views) have no `name`: the form submits every named one on change.

### The Battle Vantage's window

`apps/battle-vantage.js`, three parts (`templates/battle/`): `turnbar` (with the turn order), `net` (the map of minds' container) and `side` (the tabs). `BattleVantage.refresh()` draws `turnbar` and `side`; the map of minds is drawn again (`#mount`) only when its part was, or when what it shows has changed (a signature of its nodes, lines, symbols and focus).
- **The turn bar** (`battleContext`): one `primary` by state (Begin Encounter, Play it, Next Turn, a spotlight, Settle the aftermath, End Encounter; Stop while a Fast Fight runs) and a `secondary` beside it (Skip to Next Turn, End Encounter); the battle's menu holds the toggles and Rewind This Encounter (two presses: `data-keep-open`, `is-armed`).
- **The queue** (`context.queue`): a reaction being rolled and a player's turn to review hold the battle up (`blocking`); then the held notes, players' damage and deals. The window keeps which are blocking (`#seen`): a new one brings Waiting to the front. Next Turn carries their count (`data-waiting`), and `#onContinue` asks before moving on past them. Only the Vantage's button is held, not the chat card's or the tracker's.
- **The review's picks** are kept as they're made (`#keepDraft`, by battle, creature and events) and put back after each drawing, so a tab or encounter change loses nothing.
- **The map of minds' layout** (`#layoutFor`) is kept only while the window is open: closed and opened again, it's laid out from the map. Its **Reset** (`ff-net-reset`) is enabled once a node is dragged.

### The survey and the token's tab

`apps/player-survey.js` (`templates/player-survey.hbs`) and the token's FastFighting tab (`apps/token-tactics.js`, `templates/token-tactics.hbs`) share the questionnaire, `templates/partials/tactics.hbs`, drawn from `questionsContext` (`foundry/tactics.js`); the planner's Details shows it too.
- **Sections:** `QUESTION_GROUPS` sorts the questions into Fighting, Spending, Looking after others, and Talking and leaving. These windows draw again on every answer, so each section's `details[data-tactics-section]` remembers being open, by actor, until the page reloads (`listenTacticsSections`).
- **Playstyles' order:** `movePlaystyle(actor, id, dir)`.
- **Two presses:** Lock-in (`lockIn`, then again) and, while the player's vote is open, I'm ready (`readyArmed`). Either disarms after 6 s or on Cancel.
- **The token's tab** sits in Foundry's form, so it strips its controls' `name`s, moves their `data-action`s to `data-ff-action` and handles them itself (`movePlaystyle`, `adhd`, `resetAll`).

### Fast Fight

The Battle Vantage's **>> Fast Fight >>** (`foundry/fast-fight.js`, pure but for Dice So Nice, tested in `tests/fast-fight.test.js`; played by `live-battle.js` `fastFight`):
- **Offered** (`fastFightOffered`) in a battle begun and not over where the planner's Players run their characters is off or `battle.data.players` is empty; while it runs, as its Stop.
- **State:** `battle.fast` (`{had, pending, moment, since}`: the players' characters as it began, the place its own move on left, where the fight stood (`fightMoment`) and the turn it last changed), in the playing browser's memory only, never on the transcript: a reload or another GM picking the battle up has none.
- **Turns:** `settleTurn` asks `afterTurn`: a turn FastFighting played goes `"on"` (no `waitCard`, `moveOn` at once, as Play to the end), kept with `keptTurns` like any other, so Rewind works turn by turn. `goFast` starts it where the battle is (a played turn moves on, an unplayed one is played), unless a move of its own (`pending`) or a turn change (`turnsWaiting`) is already on its way.
- **The tracker:** `moveOn` notes where it moves on from; `onTurnChange` asks `fastTurnChange`: its own move (`"ours"`), the order changing in the same round as a combatant joins or leaves (`"same"`: the same combatant at another place, or another at the same place), or anyone else's use of the tracker (`"theirs"`), which stops it.
- **Stops** (`checkFast` → `fastFightStop`): Stop, Next Turn, Rewind, Rewind This Encounter or Play to the end pressed; `failed` (the queue's errors, and `moveOn`'s); `finish`; a player's character's turn (`turnBegins`) or one more in `battle.data.players` (`addPlayer`, `automate`); a GM wanted (`gmSettles`, `ask`, `askDamage`, `playerRolls`, `review`, a spotlight with no one to give it to); a turn change not its own. Two whole rounds with nothing changing (`stillSince`, `STILL_ROUNDS`: the turn it last changed come round twice more, or three rounds on) aren't a stop of their own: once the fight has played the system's fewest Max rounds (`rangeOf("maxRounds").min`, wherever the still rounds began), `askStill` asks the GM, and on, it counts afresh from that turn and isn't asked again for `STILL_AGAIN` (4) more rounds (`battle.fast.least`). Max rounds is the simulation's alone: a live battle never ends as a stalemate. A turn under way finishes and gets its card. The GMs are told why for `FAST_STOP_NOTES`.
- **The same GM signed in twice** (`foundry/twin-sessions.js`, `twinHeard` tested in `tests/twin-sessions.test.js`): Foundry's active GM is a user, so both sessions are it and the system's turn-start and turn-end updates (PF2e's `roundOfLastTurn`) run in each. A combatant's update carries the turn its sender saw (`Combatant._preUpdateOperation`'s `combatTurn`), and the server and every client set the encounter's turn to it with no turn change told: the session behind sends the tracker back under a Fast Fight, which then plays turns again or waits on one already played. Each browser says hello on the module's socket (`"socket": true`) at ready, the same user's other sessions answer, and a goodbye on unload takes the twin (and its notice) away. The GM is warned once per twin; `fastFight` doesn't start while `twinSession()` finds one (asked afresh, `ANSWER_WAIT`, only when one was heard from).
- **Play to the end** is off while it runs: pressing Fast Fight clears `battle.data.auto`, the toggle is disabled, and `setPlayThrough(true)` stops it. So its rolls stay in the chat (`showRolls` without `settle`, `showTurnCard` the system's cards), never on the GMs' tally card.
- **Moves:** `playMoves(..., {speed})`, `FAST_MOVE_SPEED` grid squares a second (`TokenDocument#move`'s `animation.movementSpeed`; 10 otherwise). Every move still animates; displacements (`sendOff`, `carryInside`) are unanimated as in any turn.
- **Dice So Nice** (`hushDice`, `unhushDice`, `registerQuietDice`): while it runs, this browser's `game.dice3d.messageHookDisabled` is true (the value before kept and put back by `endFast`, from every stop, `failed` and `letGo` included), and each chat message this browser creates gets `flags.dice-so-nice.skip` in `preCreateChatMessage`, so no client throws its dice. A roll message so made fires `diceSoNiceRollComplete` here once created, since nothing else would (PF2e's critical hit and fumble cards wait on it). No setting is written, so there is nothing to restore after a reload.

## Writing a system helper

```js
const KNOWN_API = [22]; // the core API majors this helper knows it works with

Hooks.once("fastFighting.init", api => {
  const major = Number(api.major) || 0;
  if ( major < Math.min(...KNOWN_API) ) return; // too old a core: tell the GM, and don't register
  // (A major not in KNOWN_API: register anyway, and warn the GM it hasn't been tried with that core yet.)
  class MySystemAdapter extends api.SystemAdapter {
    get label() { return "My System"; }
    get rules() { return myRules; }                  // pure: see "The rules object"
    workerRules() { ... }                            // the same rules for the planner's background workers: {url, exportName, data} (API 22)
    canHandle(actor) { ... }
    async toCombatantSpec(tokenDoc) { ... }          // see CombatantSpec in scripts/engine/battle-state.js
    deriveTraits(actor) { ... }                      // {traits, flags, reasons}: core-api's traitsFromParts builds traits and reasons from parts
    detectLeaders(specs) { ... }                     // [{id, score, reason, bonus}], the system's ranking of who leads best
    describeRegionBehavior(behavior) { ... }         // system region behaviors -> {types, difficult, hazardous}
    term(key) { ... }                                // the system's word for "ac" / "hp" / "sp" / "money" / "level"; null: FastFighting's generic one; false: none
    itemCatalog() { ... }                            // {categories, materials, rarities}: [{key, label}], the system's kinds of item (unused at present)
    get supportsLoot() { ... }                       // does its real fight leave loot and take corpses away? (shows the loot and corpse settings)
    plannerSettings({ roster, setup, resolved, chains }) { ... } // the planner's section for this system: {title, hint, fields: [{key, label, hint, type: "pills"|"select", value, choices}]}
    applyPlannerSettings(spec, settings, context) { ... }        // setup.system's answers, onto the battle (spec.options.system)
    describeEncounter(spec, replay) { ... }          // the encounter's own record, for the planner's summary: {title, lines}
    resourceLabel(key, spec) { ... }
    describeOutcome(spec, final) { ... }             // what a fight changes on a creature, for the planner's summary
    playstyleHints(actor, spec) { ... }              // {playstyleId: -1 to 1} (API 12)
    tacticHints(actor, spec, calc) { ... }           // the system's own answers to the tactics questions (API 12, 14)
    biography(actor) { ... }                         // its biography as plain text, or {about, story, against}
    async commitConcession(giverDoc, receiverDoc, concession, { allies }) { ... } // returns undo records (allies: the giver's side, for pooled money); an item's `count`, how many (API 26)
    async takeGoods(tokenDoc, goods) { ... }         // deals (API 26): money and items (concessions, with counts) off its sheet: {goods: {items: [item data], coins}, records}
    async putGoods(tokenDoc, goods) { ... }          // deals (API 26): takeGoods' goods onto a sheet (a creature's, a pile's); undo records
    async goodsOf(tokenDoc) { ... }                  // deals (API 26): everything a pile holds, as takeGoods' goods
    async dropValuables(scene, { x, y }, goods, { name }) { ... } // deals (API 26): the system's own loot pile, a token at x, y: {tokenUuid, records}
    skillsOf(actor) { ... }                          // deals (API 26): its skills [{key, label, mod, talk}], talking ones (persuade, deceive, intimidate) marked
    giveables(actor) { ... }                         // deals (API 26): what it could hand over: {money, denominations, items: [{id, name, img, quantity, value}]}; only what it carries put away, never what it wields or wears (takeGoods the same, but for a fallen foe robbed: `how: "loot"`)
    mainCoin() { ... }                               // the coin prices are said in, {key, label, value} (API 26: the planner's team cash; else the second largest coin)
    partyMembers() { ... }                           // the system's own party, its actors' ids (API 29): on the Friendly Team unless their token is Hostile
    settingDefaults() { ... }                        // the core's settings as your system has them (API 28): {maxRounds: {min, max, default}, loreBoost: {default, name, hint}}; name and hint, your own words
    appetite(actor, spec) { ... }                    // food (API 27): {diet: "meat"|"any"|"plants"|null, hunger: 0..1, cannibal}, by your system's own idea of nature; leave it out where your system keeps no food (no one hungers)
    meatFor(actor, spec) { ... }                     // food (API 27; corpses API 30): the corpse its body leaves on death, {item, quantity: portions}, or null. API 30: one item, flags.fast-fighting.corpse "fresh" (food: your food type, else your miscellaneous; flags.fast-fighting.portions) | "rotten" (undead) | "scrap" (metal, mechanical), the last two your miscellaneous type, quantity 0
    isFood(item) { ... }                             // food (API 27): {portions, meat} for a thing that can be eaten, else null (a fresh corpse: its portions flag, foundry/food.js corpsePortions)
    pileContents(tokenDoc) { ... }                   // piles (API 27): what a pile holds, for the engine: {money (smallest coin), items: [{id, name, value (each), quantity}]}, everything however carried

    // Live battles (Go Live): see scripts/adapters/adapter-base.js for each one's contract.
    get supportsLive() { return true; }
    async readLiveState(tokenDoc, { spec, unit }) { ... }            // the sheet as it stands, mid-fight (by default, from toCombatantSpec)
    async commitChanges(tokenDoc, spec, changes, final, options) { ... } // one turn's change set (scripts/engine/changes.js); returns an undo record
    async commitBound(tokenDoc, bound) { ... }       // tied up or loose, on the sheet (default: the system's restrained status)
    async commitTurn(before, after, options) { ... } // what a turn did beyond the tokens (a shared pool, an encounter track); undo records
    sheetCarries(key, actor) { ... }                 // does this helper write this engine condition and read it back? (default no: the core keeps it)
    conditionLabel(key) { ... }                      // the system's own word for an engine condition, or null
    conditionChoices() { ... }                       // the system's own conditions as engine keys [{key, valued}], then super's
    liveOwnership() { ... }                          // what the system does itself at a turn's start and end ({recovery, persistent, afflictions, repeatSaves})
    readTurn(messages, context) { ... }              // a player's turn, read from the system's chat cards: engine events
    liveOpening(message, tokenId) { ... }            // a card that gives foes an opening (a ranged attack in reach)
    reactionsOf(spec) { ... }                        // its reactions, for its player's Always use it / Ask me / Never use it
    rerollResource() { ... }                         // the name of what buys a reroll (Hero Points), or null
    get liveTurns() { ... }                          // "initiative" (default) or "spotlight"
    async giveSpotlight(combat, combatant) { ... }   // spotlight systems: hand the turn over
    livePools() { ... }                              // the world's shared pools as they stand (Daggerheart's Fear)
    async placeSummons(scene, summonerDoc, action, creatures, places) { ... } // summoned creatures as tokens; {tokens, records}
    async showTableRoll(roll, { token, target, audience, flavor, flags }) { ... } // the engine's own roll as the system's card (API 20)
    async readyGear(tokenDoc, { step, actionId, gear, item, hands, secret }) { ... } // a step it took to get ready, on its sheet the system's way (API 20)
    async leaveToTable(message) { ... }              // a card of its own FastFighting won't apply after all: the system's Apply back on it (API 21)
  }
  api.registerAdapter("my-system", MySystemAdapter, { priority: 10 });
});
```

- **Declare your system** in `module.json` (`relationships.systems`) so Foundry only offers the helper in worlds of that system. The core also ignores adapters registered for another system. Among adapters for one system, the highest `priority` wins.
- **Versions.** The helper-facing API version is `major.bug`: `CORE_API = { major: 22, bug: 0 }` and `CORE_API_VERSION = "22.0"` in `core-api.js`; the `fastFighting.init` api object carries `api.version` ("22.0"), `api.major` and `api.bug`. The major goes up when what a helper can use changes (something added that a helper may rely on, or something changed); the bug number goes up for a fix that changes nothing a helper uses.
- **Compatibility is the helper's call.** The core never refuses a helper for its version and keeps no list of which helpers fit it; `KNOWN_HELPERS` in `scripts/helpers.js` exists only to recommend a helper for a system. Each helper lists the majors it knows it works with (`KNOWN_API` in its `main.js`). Below the oldest, it doesn't register and tells the GM the core is too old; on any other major it isn't known to work with, it registers and warns the GM it hasn't been tried with that core yet. The minimum in its `module.json` `relationships.requires` is Foundry's install-time check, also the helper's to set.
- **Ask for a hook when nothing fits.** When a helper builds something new that the core can't handle well enough with what it already offers, ask for a new core hook rather than forcing a poor fit or working around the core. A new hook raises the API's major, which the helper then adds to `KNOWN_API`; that is how the hooks marked "API n" below arrived.
- **Recognise things by slug, read them by what they do.** To find a particular feature, action or spell, look for its slug or identifier (PF2e `slug`, dnd5e `system.identifier`), never its name: slugs are the same in every book, every edition of the free rules and every language, while names change with translations, reprints and homebrew copies (the name is only a fallback). Better still, read what an item does (its activities, effects, rule elements, and as a last resort its words), so paid books and homebrew nobody has seen yet still work. The helpers work from the free rules (the SRD, the PF2e remaster, each system's open content) alone; anything more is read the same way.
- **Units:** the engine counts distance in feet. Give speeds, reach and ranges in feet (convert metric data); the core converts the scene's grid. Heal actions can carry `reach` (touch) or `range`.
- **Kinds of creature:** a spec may say what kind of creature it is (`creatureKind`: the system's own word, such as a 5e type and subtype or a PF2e ancestry), and the planner groups neutrals of a kind together; without it, the same stat block or name does.
- **Words:** a helper's own words live in its `languages/en.json`, as the core's do. `api.adviseTranslation(moduleId, systemTitle, knownTranslations)` makes its settings recommend the system's translation module when the reader's language isn't English and it isn't on; `api.keepEnglish(moduleId)` keeps the keys its `hardcoded-toEN.json` lists in English.
- **Publishing:** when your helper is out, open a pull request adding a row to the table in [systems.md](systems.md) and an entry to `KNOWN_HELPERS` in `scripts/helpers.js`, so GMs on that system are pointed to it.

### The rules object

The rules object is pure and is called thousands of times.
- **The turn:** `turn(u)` gives the budget (`{actions: 3}` or `{action: 1, bonus: 1, move: 30}`).
  - `mainPool` names the pool a plain-number cost uses.
  - `movement` is `"actions"` (each move costs an action) or `"feet"` (spend movement, then Dash).
  - `costOf(action)`, `basicAction`, `talkCost`, `stealCost`, `feintCost`, `firstAidCost`, `shieldCost` and `standCost(u)` set what things cost.
- **Rolls:**
  - `degreeOfSuccess(natural, total, dc, kind, die)` returns 0–3, where `kind` is attack, save or check, and `die` (when it isn't a plain d20) is `{faces, critOn, fumbleOn}`: the die rolled, the d20-relative natural that threatens a crit (the rules scale it to the die) and the natural at or under which it fumbles;
  - `actionDie(u, n)`: the die a creature's n-th action this turn rolls (DCC action dice), when actions don't say;
  - `roll(rng, mod, dc, {advantage, kind})`;
  - `attackPenalty(action, attacksMade)`;
  - `saveMultiplier(degree, save)`, `afflictionStep(degree, phase)`, `critical(parts)` and `healCheckMultiplier(degree)`;
  - `minimumDamage`.
- **Situations:** `modifiers.attack`, `defense`, `save`, `check`, `steal`, `exposed` and `actionsLost`. The engine passes the facts (prone, grabbed, flanked, distance, allies adjacent, engaged, conditions); the rules return bonuses and advantage.
- **Damage and dying:**
  - `applyIwr(iwr, byType, target, ctx)` (ctx: what deals the damage, API 20 below; `ctx.estimate` for the Statistics Engine's estimate, API 25: change nothing) and `critImmune(target, action)` (true: a critical hit on it deals a normal hit's damage, still a critical hit for everything else: PF2e's immunity to critical hits);
  - `onDropped(unit, {crit, model, amount, overflow})` (it may leave the unit `beaten`: out of the fight, alive, however the table decides; one who would kill it, the Cruel or a creature that isn't a player character unless it holds back, kills it instead, and the story says so), `onHealed(unit, amount)` and `recoveryCheck(unit, rng)`;
  - `firstAidDC(unit)`, `firstAid(unit, degree)` and `persistentFlatCheck(rng, {run, unit, type})` (the run and whose it is, for a live battle's flat check the system rolls: `systemRolled`).
- **Crowd control, buffs and debuffs:**
  - `isImmune(target, action)`, `controlShift(ctx)`, `conditionWeight(key, value)`, and `conditionMods(key, value)` (a condition as bonuses and penalties, so it's weighed like any other: PF2e frightened 1 is -1 to everything);
  - `defenseDc(target, against, by)` (the DC a skill action rolls against, `by` the one rolling where there is one: DCC's grapple by size; default 10 + the defense, or against AC the AC itself) and `resistShare(value)` (how much of a blow a resistance stops; default half);
  - `concentration: {save, dc(damage), breaksOn: [conditions]}`, where the system has it.
- **Doors:** `door` (the typical door: defense, hit points, DCs and whatever its own rules use), `doorCosts` (`open`, `force`, `pick`), and `doorDamage(door, damage)` (how much of a blow gets through). The helper puts `doorWork: {force: {mod}, pick: {mod}}` on each spec. `tryDoor(run, unit, door, {method, mod, dc})` plays a force or pick try the system's own way (`{success, degree, said: {text}}`, or null for the core's check: Ironsworn's Face Danger, with its momentum); a strong hit on a door uses the action's `critDamage` where it has one. A GM can give a door its own numbers in the wall's flags (`fast-fighting.door`).
- **Breaking free, and freeing a friend** (`behavior/holds.js`): on each spec, `escapeWork: {mod, faces}` (its best way out as a check: Athletics, Acrobatics, an unarmed attack) and `escapeDC` (how hard its own grab is to break); on an effect, `escape: {dc, others}` (an action breaks it; `others: "untie"`: a friend frees it with an action and no roll; `"check"`: with a roll; none: it can't). The rules may add `holds(run, unit)` (holds of its own: manacles, being swallowed), `escapeFrom(run, unit, key)` (a condition its sheet shows that an action breaks: `{dc, others}`), `bondsDC(unit)` (FastFighting's improvised bonds), `escapeCost(unit, hold)` and `untieCost(unit, friend, hold)` (what a try costs), and `breakFree(run, who, hold, {freeing})` (the system's own try, for itself or a friend: `{success, degree, natural, mod, total, dc, said}`, or null for the core's).
  - What needs hands: `action.hands` (free hands it needs: 0 for a spell with no gesture, a bite) with `rules.handsKnown` (the helper says it of every action); otherwise weapons do, natural attacks (`action.natural`) don't, and spells as `rules.tiedStopsSpells` says (a helper setting).
  - What else an action ends: `rules.remedies(run, unit)` (`[{key, cost, annoyance, label, condition, try(run, unit)}]`; one for a core condition, by its `condition`, in place of the core's own), and for persistent harm `rules.persistentRemedy(run, unit, type)` and `rules.persistentRemedyCost(unit, type)` (by default one more try at the system's recovery, for the basic action).
- **Reactions:** `opportunity(reactor, mover)` returns the strike a creature makes at a foe leaving its reach, or null if it can't; `reactions(u)` (default 1 a round); `disengage(u)` returns `{cost, label}`, how to leave safely. `bestReactionStrike(u)` in core-api picks the usual strike.
- **What's typical for a level:** `typical.ac`, `save`, `skill` and `dc`.
- **Per-fight state:** `initUnit(u)` and `capture(u)`.
- **After the fight:** `recoverBody(u, rng)`: a dead player character's last chance once friends reach it (DCC: roll the body). It sets the unit's status and hit points and returns the line to log.
- **The story:** an attack is told by its **damage family**: how the harm looks, never the type's name (only the Statistician's log names types). The families: bludgeoning, piercing, slashing, ballistic (gunfire), explosive, bleed; fire, cold, electricity, acid, sonic, force, laser, plasma, radiation, gravity, time; wind, water, earth, plant; vitality (life), void (death, necrotic), radiant (holy light), unholy (profane); mental (psychic), spirit; poison; untyped.
  - Map your system's every damage type onto the nearest with `storyDamageType(type)` (5e: lightning → electricity, thunder → sonic, necrotic → void, radiant → radiant, psychic → mental; a type it doesn't know is told as untyped).
  - Where you can tell more than the damage does, name the family on the action, by slug or id: `action.storyType` (a firearm group is `"ballistic"`; a laser rifle that deals fire is `"laser"`; a plain blow with the air trait is `"wind"`). Otherwise the core reads the attack's name against the language file's word lists (`FASTFIGHTING.StoryWords.<family>`: "Laser Pistol", "Wind Blade"), but only to tell more than a plain blow or plain magic, or fire or lightning that is really a beam or a blast ("Plasma Cannon"), never over damage with a look of its own ("Life Drain" dealing void stays void).
  - An attack that deals several types is told by the one that shows: magic or energy over the blow that carries it, then a blast, then gunfire. A ranged strike sends a shot (the "Shortbow shot", never the bow itself striking) unless it is marked `action.thrown` (a javelin, a dagger, a bomb: the weapon flies itself).
  - **Precision damage**, harm with no look of its own added to a blow (a sneak attack, a backstab, a precise strike, a critical's extra dice of no type), is a damage part marked `category: "precision"` (or of type `"precision"`), its type the weapon's. A hit that carries it is followed by a sentence on how surprising, shocking or subtle it was, and it never changes the family. PF2e's formulas say "precision" themselves; 5e's sneak attack and DCC's backstab are marked by their helpers. `rules.applyIwr` hears how much of each type a category's parts dealt (`ctx.byCategory`: precision, splash), for an immunity, weakness or resistance to it.
  - **Maneuvers and conditions** are told from one master list ([docs/story-maneuvers-conditions.md](docs/story-maneuvers-conditions.md): 73 maneuvers, 61 conditions, each with its own sentences, an over-the-top one and an underwhelming one). A control action's maneuver is read from its id's last part by slug (`…trip`, `…demoralize`), or named outright (`action.maneuver: "distract"`). The conditions it lays are mapped by key (common names such as off-guard, grappled, enfeebled or fatigued are known), or by `storyCondition(key)` in your rules where yours differ (Daggerheart's Restrained is `immobilized`; `false` for one that isn't told in a fight at all, such as Ironsworn's burdens). Reactions have a master list of their own: [docs/reaction-triggers.md](docs/reaction-triggers.md).

#### Maneuvers, the map, conditions and afflictions (API 16)

- Maneuvers (`engine/maneuvers.js`): a control action names one (`action.maneuver`: shove, drag, reposition, fling, trip, grapple, disarm, feint, demoralize, cheapShot, blindFoe, trample, sunder) and takes its results by degree unless it gives its own. A result can `move` the target (`{kind: "push" | "pull" | "place", feet}`, or `{kind: "push", to: feet}` to push it until it's that far off), `grab` it, deal its own `damage` at that degree only, or with `self` land on the one who tried (moved by the target, or held by it). The same results land from a deed's tier, a paid rider (`spec.riders`), a crit table's row, a blow's rider (`{kind: "move", move, critOnly}`; or `{kind: "control", control}`, a maneuver with its own roll: API 20) and a failed save rider (`move`, `grab`). A `demoralize` is words as well: its degree, against its own DC, counts as an intimidation at its target too (`talk.js` `resolveTalk`, no roll of its own), as a player's Demoralize card does in a live battle: a success wears its will to fight, a critical failure offends it.
- Forced movement (`behavior/forced.js`): `rules.fallDamage(feet, unit)` (damage parts), `rules.fallProne` (true, false, or `(unit, dealt)`), `rules.collisionDamage(unit, {feetLeft, into, move, by})` when a push is stopped short. The ground comes from the scene (`spec.ground`: heights, difficult and hazardous cells, walls).
- Room (`behavior/space.js`): the spots a creature looks for (beside a foe, to shoot from, to end its turn on, a step) are the map's squares, the grid it began the fight on, wherever a move left it (`gridOf`). Nobody's move ends in another's space unless `rules.endIn(run, mover, other)`; getting past one is `rules.passThrough(run, mover, other)` ("free", "difficult", "around", "tumble"), and a tumble `rules.tumbleThrough(run, mover, other)` (`{success, natural, mod, total, dc}`; through it as through difficult ground unless `difficult: false`).
- Sight past walls (`spec.walls`, from the scene): ranged attacks need a clear line from where the attacker stands. Cover reaches the system's rules as `situation.cover` and a save's `cover` (`"none" | "some" | "most" | "total"`); a system with its own rules for it sets `rules.handlesCover`, else three quarters hidden or more adds `COVER_POINTS` to AC and saves. core-api exports `coverOf`.
- Conditions (`engine/conditions.js`): many of the core's own do something where the system says nothing of them (`PROFILES`: penalties, losing actions, harm each turn, holds, remedies, countdowns, spreading, out of reach). A system that gives one its own meaning claims it (`rules.ownConditions`, or `rules.conditionMods` for it); `rules.conditionHarm(key, value, unit, by)` puts a condition's harm in the system's terms; `rules.toughSave` is the save against what spreads (default the best of Fortitude, Constitution or Strength); flat penalties are in d20 points, scaled by `rules.rollPoint`. `CONDITION_SYNONYMS` and `coreKeyFor(word)` map a system's own names onto the core's keys.
- **Fear** is the system's to say: `rules.conditionWishes(run, unit, {key, value, by})` returns what a condition makes a creature want while it lasts (`[{kind, targetId, level}]`, `[]` for nothing, or null for the core's reading: keeping away from whoever frightened it), and `rules.fearConditions` names the system's own fears beyond frightened, fleeing and turned. A system whose fear has steps of its own (PF2e's frightened 2) says `rules.fearValued`, and the core goes by them; otherwise a fear that's only there or not builds, hidden: each fear that lands (or is laid again) a step more, each that lapses a step less, none once none is left. A condition's wishes never send a creature running or out of the fight. Only its own fear does: its nerve (morale), or its fear made worse and worse past what its nerve bears (three steps, two for the timid, four for the brave), and that goes when the system lowers the fear or lets it lapse.
- Damage parts with `direct: true` (all of a hit's) reach `rules.applyIwr(iwr, byType, target, {direct})` as direct (Daggerheart: no Armor Slot). A reaction to being hurt may carry a `move` (the one who hurt it knocked back, on a failed save where it has one).
- An outcome's `resources` (`{hope: -1}`) are gained or lost wherever it lands (a blow's rider, a maneuver's degree, a deed, a buff), and an action's `resources` with its heal, through `rules.gainResource`; `rules.outcomeWorth(run, by, target, outcome)` adds the system's own worth of an outcome, for what in it only the system can value. An action may have `uses` beside a resource cost (a Fear, once a scene). An environment's summons are called on its turn, whatever its tactics.
- Afflictions (`behavior/afflictions.js`): a stage's `duration` (a save at its end), `virulent`, `stacks` (a fresh exposure worsens it: by default not for a disease or a curse), `tally: {cure, keep}` (5e's three successes or failures), no `save` (it simply takes hold); `simpleAffliction({key, most, every, save, ...})` builds one whose stage is a condition's value.
- Healing over time an effect lends: `outcome.fastHealing` (hit points each turn) and `outcome.regen` (`{amount, stoppedBy, needsHp}`); the `unhealable` condition stops all healing.
- Summons appear in the nearest free space to where they'd want to be, within `action.range` (feet, or `{max}`; default 30) and the summoner's sight.

#### Heals, conditions, holds and the Statistics Engine (API 17)

- A heal's `outcome` lands on the one healed where the heal took (5e Regenerate's `fastHealing`, PF2e's `regen`), and counts when heals are weighed. `rules.usable(run, u, action, target)` is asked of heals too (PF2e: one sickened drinks no potion).
- A blow's rider honours its `maxSize` and the system's immunities to it (`rules.isImmune(target, {traits, onSave: [rider]})`) as a failed save's does: 5e's Push mastery, Large or smaller. `hurtOnly` on a rider: only when the blow hurt (Daggerheart's Bear). A save rider (`kind: "save"`) may also carry `traits` (its own kinds: `poison`, `disease`; one immune to any of them is spared it, save and all) and `slay` (a failed save kills outright, as a crit row that slays: DCC's "DC 15 Fort or death"), both API 29; the Statistics Engine counts a slaying rider as a few blows' worth.
- An affliction with `bySave`, laid by a save action, takes hold as that save went (`rules.afflictionStep(degree, "exposure")`: PF2e's spell, a critical failure stage 2; 5e's Contagion), rolling no save of its own; its `save` is for later (its stages, its tally).
- A `rules.remedies` entry with `condition` (one of the core's keys) is tried in place of the core's own remedy for it. `rules.conditionProfile(key)` changes part of a core condition's profile, the fields it names in place of the core's (null drops one): `{mods: null}` keeps the harm and the hold but not the penalties (5e's own Disadvantage inside a gullet), `{remedy: null}` (no scraping corroding off), `{harmAt: "start"}` (its harm at the start of the bearer's turns: 5e's Burning).
- Swallowed and engulfed, in every system (a profile's `inside`): the one held is where its holder is and goes where it goes, its holder's grab on it ends, it reaches its holder from inside, and nothing outside reaches it, nor it anything outside (total cover; others inside with it, yes). core-api exports `holderOf(run, u)` and `cutOff(run, a, b)`. `rules.letGo(run, u, key, holder)`, as a holder falls: what comes of being let go (5e: out Prone), or `false` to keep hold (PF2e: a Swallow Whole corpse, to be cut open first).
- The Statistics Engine weighs a condition's harm in the system's terms (`rules.conditionHarm`, not the core's dice), that a foe held inside fights none but its holder, an affliction's stages' conditions as well as their damage, and an option only one foe allows (`rules.usable` says no to the rest): clearly better, it goes for that foe (2014's behir swallows the one it's grappling).
- Holds: an effect whose escape condition is gone is no hold, so what it laid with it clears as it's broken. `rules.breakFree` may return `harm: {byType}`, what the try does to whoever holds it (damage as rolled, against its resistances: cutting free of a gullet).
- What a roll is for: `modifiers.check` hears `{unit, target, purpose, skill, action}` (purpose: talk, goad, theft, firstAid, sizeUp, notice, seek, heal, aid or control; the skill a spec names); `modifiers.save`, and `adjustRoll` and `afterRoll` on a save, hear the `action` it's against and `from` whom.
- `rules.disrupted(run, u, action)`: a spell (a magical action) that comes to nothing as it's cast, lost and told (`{natural, dc, said: {text}}`: PF2e's stupefied flat check).
- `rules.afterHarm(run, u, amount, rng, {by, types, byType, action, crit, lingering})`: who did it, and with what. `rules.afterAttack(run, u, target, {action, degree, dealt, control})`: once an attack's damage, and everything it laid, is done (PF2e: a hidden attacker seen only now).

#### Players' damage (API 19)

A player's damage card in a live battle, at a creature FastFighting runs, is applied at once (the **Apply players' damage** setting, the planner's per-battle toggle, the Battle Vantage's for now; off by default) or waits in the Battle Vantage for a GM (Apply, Half, Double, Dismiss; one with a save to roll first, several targets or none always waits). Three optional adapter hooks, none by default:
- `damageCard(message, {ids})`: `{amount, kind: "damage"|"healing", targets: [tokenId], save}` for a damage roll, else null.
- `applyDamageCard(message, token, {multiplier, amount, ...})`: applies it through the system's own damage handling (`amount`, in a turn FastFighting plays: the engine's own sum after the target's resistances and its share, for a system whose application has no resistances: DCC's stat lines) and returns undo records (`undoRecord`, the values as they were), kept with the player's turn for Rewind. Also applies the damage of a strike rolled with `rollStrike` (below); a reaction whose spec says `applies: "shieldBlock"` (the system's application does it: PF2e's Shield Block) comes as `{shieldBlock: true}`, `applies: "halve"` (5e's Uncanny Dodge) as `{halve: true}`.
- `appliesPlayerDamage()`: the name of the system's (or a module's) own setting that applies players' damage, while it's on, else null. While it is, FastFighting's toggles are greyed out and apply nothing.
- `damageApplied(message)` (core-api, API 20): did FastFighting apply this damage card itself, or settle it by its own sum, in the live battle this GM's browser plays? Whoever made the card: a player's damage card applied for them, a strike's or a save's card applied the system's way, a reaction's strike rolled on its player's screen or by its player. The ids are noted with the turn that applied them (`turn.applied`, a player's turn's `pc.applied`: `live-battle.js` `noteApplied`, `foundry/applied-cards.js`), never read from a flag on the card, which anyone can set on their own; each card is drawn again (`ui.chat.updateMessage`), so a helper's `renderChatMessageHTML` takes the system's Apply buttons off it (PF2e's `cards.js`). A rewound turn's cards get them back.
- `rollStrike(token, {action, target, attackNumber, advantage, secret, pulled})` (`pulled`, API 31: the blow is struck to knock out; the system's roll carries what that costs, PF2e's −2): a strike rolled with the system's own roller, its cards in the chat: `{attack: {degree, natural, total, dice}, damage: {byType} | null}` (damage as rolled, before resistances), or null (the engine rolls it). `dice` (optional, numbers): the system's own dice as they fell, for `rules.asRolled` (Daggerheart's `{hope, fear}`). `attackNumber` is the attacks made before it this turn (for a multiple attack penalty; 0 for a reaction); `advantage` (API 24) the engine's net advantage on it (1 advantage, -1 disadvantage, 0 neither), for a system whose roller has it; `secret` rolls it for the GMs only (the GM keeps its name secret). `records` (API 20): undo records for what the roll changed on the striker's own sheet beyond its cards (PF2e's ammunition, loaded and spent), kept with the turn for Rewind, even where the result says no degree (`{records}`); only the striker's own token and actor, and only their data and items, are kept (`live-battle.js` `rollRecords`).
- `useAction(token, {action, targets, secret})`: an action's own card as its user shows it (a spell's, a breath's), nothing rolled or spent: `{card}` or null. `rollDamage(token, {action, card, secret, target})`: the damage of an action that isn't an attack, rolled once for all it catches: `{damage: {byType}, card}` or null. `target`: the token it's aimed at first; `action.strikeOf`: the Strike whose damage it deals with no roll of its own, where the helper's action names one (PF2e Rend), to roll with that Strike's own damage roller. In a turn FastFighting plays, a spell, a save or auto action, a buff or heal with no check of its own, and a control action that says `card` (API 20) ask for their card first (`use`; the helper says null where there's none to show); a save's or an auto's damage is rolled by the system (`damage`), each target's share (its save's multiplier, rounded down) applied with `applyDamageCard` (`apply`, with `multiplier`), and the target takes what its sheet lost.
- `adjustRolled(token, {card, adjust, secret})`: a change the helper's rules made to a roll the system made, carried out on its card the system's way (Ironsworn's momentum burned). The rules ask it from `adjustRoll` when `ctx.rolled` (`run.live.roll(run, {kind: "adjust", unitId, card: roll.card, adjust})`; the roll's `card` is what its rollSave or rollCheck named) and keep the roll as it fell where it comes back `{done: false}`.
- `rollSave(token, {save, dc, action, from, advantage, secret})` and `rollCheck(token, {purpose, skill, against, attackNumber, standoff, dc, action, target, advantage, secret})`: a save or a check rolled with the system's own roller, its card in the chat: `{degree, natural, total, dice}`; `{gm: true}` where it needs a GM's judgment the helper's code can't make (a GM picks how it went, or lets FastFighting roll it); or null (the engine rolls it). A player's character's is rolled on its player's screen while they're here. `purpose` is `control`, `talk`, `aid`, `heal`, `firstAid`, `escape`, `theft`, `disengage`, `cast` or `seek` from the core, and whatever a helper's own rules ask through `systemRolled` (PF2e: `flat` for a flat check, `tumble` for Tumble Through); `attackNumber`, for a check with the attack trait (`check.attack`), is the attacks made before it this turn, as the engine counted them for its own penalty. `standoff` (API 20) is true while a standoff holds, no blows struck yet, for a system whose words differ then (PF2e's talk: Make an Impression, not Request). `advantage` (API 24): as `rollStrike`'s, where the engine knows it (a save's, an affliction's, concentration's; an aid or heal check's).
- **The system's rolls in a turn FastFighting plays:** `run.live.systemRolls` lists the kinds the helper makes (`strike` with `rollStrike`; `save` with `rollSave`; `check` with `rollCheck`; `use` with `useAction`; `damage` with `rollDamage`; `adjust` with `adjustRolled`; `card` with `showTableRoll` and `applyDamageCard`, API 20: **Table rolls** below; `apply` with `applyDamageCard` and a strike, damage or card roller). Saves and checks are asked for where the engine would roll them (`battle-state.js` `systemRolled`, then `rollCheck`'s `rolled`): no Luck, momentum or rescue after a roll the system made. A helper's own rules that roll a check themselves (`rules.breakFree`) ask the same way: `systemRolled` and `rollCheck` (with its `rolled`, so `rules.asRolled` makes the roll theirs) are in core-api. While `liveTurn` plays (`run.live.playing`), each strike asks for its roll (engine/live.js `systemRoll`: `NeedsDecision` with `roll: "strike"`, keyed so a replay finds its answer); the live side plays the turn's moves so far on the map (so the system measures range and flanking from where they stand), rolls it, and plays the turn again with the answer (handing each pass the one before it, `liveTurn`'s and `movedBeside`'s `before`: it takes up the round's reckonings that pass had worked out, so a turn played again goes the same, sooner). A hit's damage card is then applied the system's way (`roll: "apply"`), and the target takes what its sheet lost; one a reaction lessened (other than one the system applies itself) takes the engine's sum. Every card and undo record is the turn's, for Rewind. Outside `liveTurn` (a foe's reaction in a player's turn, planning, a sample fight) nothing is asked. A live battle's area test reads where the engine has everyone, not the tokens, so a turn played again tests the same.
- **Players who drop out** (`foundry/away.js`, pure, tested in `tests/away.test.js`; run by `live-battle.js` from Foundry's `userConnected(user, connected)`, only in the browser that plays the battle). A player (not a GM) disconnects, with `autoPlayAbsent` on: each character the players run that they own (a summons, its summoner's players too) left with none of its players connected gets a countdown of `autoPlayAbsentSeconds` (30 to 600, default 120), kept in `battle.data.awayTimers` (`[[unit id, deadline ms]]`) so a reload resumes it, one timeout per deadline (`deadlineClocks`), stopped when the battle ends or the browser lets it go. A player not connected as the encounter begins counts as gone since `beganAt`. A reconnect stops their characters' countdowns at once; still connected `BACK_AFTER_MS` (12 s) later, every character they own that FastFighting plays is handed back, however it came to be ticked, and the GMs are told; a disconnect within the 12 s cancels that (`joinWaits`). A GM's tick or untick clears that character's countdown; the setting turned off stops them all (`settings.js` `followSetting`). - `areaShape(data, {area})`: an area on the map as the system draws it. The engine's own test (`inArea`, off the live map) reads the same.
- **A player's turn, rewound whole:** as it begins every creature's token and actor is noted in the GM's browser (`captureSheets`), and kept with the battle (`pcs.<id>`, written once a turn), so a reload or another GM picking it up can still rewind it; as it ends, what changed since becomes undo records first in the turn's (`sheetUndo`: token moves, the actor's system data, items changed, used up or added, effects), so a Rewind puts them back last, after FastFighting's own. A turn still open is taken back the same way (`revertOpenTurn`). Taken back whole (by Rewind, Previous Turn past it, or Rewind This Encounter), a player's turn takes its player's own cards with it (`undoEntries`); the one the tracker goes back to is reopened with its cards, read again when it ends. Rewind This Encounter then sweeps the chat for any other card a creature in the battle made since it began (`battle.data.beganAt`; `strayCards`: a roll, the system's own card, or an action's card with a heading; words alone stay; only one by a GM or one who owns the creature). A turn takes only its own cards: those the GM's browser made, and its player's speaking for their character (`turnCard`, `madeFor`); nobody else's chat, so a Rewind never deletes it.
- **A system's own lines about FastFighting's writes** (`foundry/side-lines.js`; the decision, `sideLine`, pure and tested in `tests/side-lines.test.js`): some systems post a chat line by themselves for each sheet change (foundry-ironsworn's change log: "+2 momentum (now 4)"). While a turn is written (`writeChanges`, the helper's `commitTurn`: `writingFor`), each such line is marked as the battle's (`flags.fast-fighting.live.battle`) and goes into the turn's cards once made, so a Rewind deletes it with them, and Rewind This Encounter with the battle's. While a Rewind takes the writes back (every `revertEntry`: `takingBack`), none is made. A side line is one this browser's user makes, with no dice, not FastFighting's own, speaking for an actor in the battle; anything else posted meanwhile is left alone.
- `namesFollowNameplates()`: true where the system lets token nameplates decide whether players learn an NPC's name (PF2e's Tokens Determine NPC Name Visibility); the story then names a creature only where its nameplate shows to everyone. Otherwise it's named once a player's character has seen it (in sight, or it came to blows or words with one), unless the GM ticked **Keep its name secret** on its FastFighting tab.

A creature the blow leaves at 0 hit points that the system left standing falls by the battle's rules at once (`liveDrop` on a copy of the fight, written through `commitChanges`), so the players see it; the turn's reading at its end still credits the blow.

- **An outcome for another alone:** `outcome.notSelf` never lands on whoever laid it, and is worth nothing to it
  (`effects.js` `applyOutcome`, `outcomeWorth`; a heal's in `simulator.js` `executeHeal`): PF2e Lay on Hands' +2 AC, on
  any friend it heals but the champion.
- **A heal of so many hit points** (no dice: PF2e Lay on Hands' 6) is a table roll all the same, its `parts`' numbers
  (`engine/table-rolls.js` `flatHeal`), so its card says whom it heals and how much; the plain roll shows its number.
  A heal's table roll carries its action's id (`action`).
- **A heal in a turn FastFighting plays** is the system's healing card (`card`, the rolls waiting before it shown first:
  `engineCard`), applied the system's way (`apply` with `healing: true`, its `multiplier` a heal check's), and the one
  healed gains what its sheet gained (`{gained}`; `simulator.js` `healedLive`). Null (no card, or the table settles it):
  the engine's own heal, written with the turn's changes. The helper's `applyDamageCard` applies a healing card as
  healing (PF2e's posts its own "is healed for N" card).
- **What an effect laid, and whose:** `captureUnit`'s `laid` (effects that lay conditions alone: `{key, sourceId, label,
  conditions}`, only where there are any) and the change set's `laid` (those new this turn), beside `effects.added`
  (bonuses, resistances, a mark), so a helper can name who got what.
- **The cards a helper posts as it writes a turn** (`commitChanges`) are the turn's: `live-battle.js` `writeChanges` keeps
  the ids it made (`messages`: a turn's, or a player's turn's `rollCards`, `cardsOf`), so Rewind deletes them.
  `commitChanges` hears `options.tokenOf(id)` (a creature's token, by its id in the run: an effect's `sourceId`) and
  `options.audience(id)` (`"public"` or `"gm"`: `table-rolls.js` `audienceFor`, the GMs alone for one hidden from the
  players), for a card it posts.
- **Player to player:** `live-battle.js` `tableSettles({applyDamage, playersRun, by, target})` (pure): a player's
  character's heal, damage, buff or debuff at another player's character (`spec.kind` "pc", or one a player owns; never
  one at itself), FastFighting playing it for an absent player or not, while the battle's Apply players' damage is off

  - the next sync reads back whatever the table applied (`syncFromSheets`: its hit points and status, the sheet's);

#### The planner's fights on background workers (API 22)

The planner's prediction and its swing factors run on a pool of module Web Workers, so the screen never freezes for a
fight and more fights fit the time (`engine/batch-pool.js`, `engine/batch-worker.js`; `foundry/battle.js` `simulate`,
`swingFactors`, `fightPool`; `tests/api-22.test.js`).
- **The hook:** `adapter.workerRules()` returns where the workers import the system's rules from: `{url, exportName,
  data}`. `url` is the rules module's, from the helper's own (`new URL("./rules.js", import.meta.url).href`: Foundry
  serves it under `/modules/<id>/`, whatever its route prefix; a relative one is read from the page's); `exportName` the
  export that is the rules object, or a function the worker calls with `data` to make them; `data` the settings those
  rules read, as plain data (anything a structured clone copies). Null (the default; an older helper): the main
  thread's `runBatch`, as before. The core's generic adapter gives `scripts/adapters/generic/rules.js`.
- **What the rules may touch:** nothing of Foundry's, at import or as they play. The module, and everything it imports
  (core-api.js is fine), must load in a worker: no `game`, `CONFIG`, `canvas`, `ui`, `foundry`, `Hooks` or `document`.
  A setting the rules read comes in `data`, or (better) on the spec, read when the spec is built. Labels for the log are
  the one exception: a fight's summary holds no words, so in a worker `game.i18n` is a stand-in that gives each key back
  (`has` false, `localize` and `format` the key), as the core's `localize` does without Foundry.
- **The spec** goes to each worker as a structured clone: plain data, no functions (`Infinity`, `undefined`, Sets and
  Maps are fine). One that can't be sent runs on the main thread.
- **The pool:** up to `MOST_WORKERS` (4), one fewer than `navigator.hardwareConcurrency` (one left for the screen), one
  at least (`poolSize`). Each worker builds its own `prepareBattle` and runs an interleaved share of the fight indices,
  fight i with `deriveSeed(seed, i)`; it posts the fights it has done every `FLUSH_MS` (25 ms). The main thread feeds the
  aggregator in index order, so N fights give exactly what `runBatch` and `runBatchSync` give for N fights with that
  seed. `preSimulate`, the modifiers and `postSimulate` stay on the main thread, before and after.
- **The time:** each worker starts no fight once the prediction's time is up (but fight 0), and finishes the one under
  way; fights done past the first one missing are left out, so the batch is fights 0 to N - 1. Its time counts from
  when the batch is sent, the workers' start included. **Stop** ends the workers at once, keeping the fights in order so
  far (fight 0 at least, run on the main thread if none came back). The planner's estimate of how many fights fit
  counts the threads (`run-budget.js` `expectedRuns`, `paceOf`: the pace is each thread's).
- **No workers:** the batch runs on the main thread (`runBatch`, in the time left) with the world's **Planner:
  background workers** off (`plannerWorkers`, Troubleshooting & data; `foundry/battle.js` `fightRules`), without Web
  Workers, or without `workerRules`. So does it once workers have failed with those rules this session: a module that
  won't load in a worker, a rules error there, a worker that can't be made, or workers that aren't done `GRACE_MS`
  (20 s) past the time. Every later batch that session runs there too, the swing factors after a prediction's workers
  failed included; the console says why, and nothing tells the GM.

#### Aptitudes (API 23)

`spec.aptitudes`: a hidden, quick judgment of what a creature is like, for the Statistics Engine alone (never shown,
never fudged): `{smart, strong, fast, wise, charismatic}`, each 0 to 4, fractions allowed (0 very low, 1 low, 2 average,
3 high, 4 exceptional). The helper works it out however its game ranges such things; a system with nothing to read
one from leaves it out. `fast` is agility and quickness, not how far it moves (`spec.speeds`).
- **Reading it:** `engine/aptitudes.js` `aptitude(u, key)`: the helper's number, held to 0 to 4; unsaid, smart 0 for a
  mindless (`social.mindless`, `flags.mindless`) or animalistic creature, else 2; the rest 2. The engine draws its
  lines halfway (`APTITUDE_AT`: dumb under 0.5, average or better from 1.5, high from 2.5), so whole bands and
  anything between read the same way.
- **What weighs it so far:** smart, in focus fire (`behavior/focus.js`: not dumb) and keeping together
  (`behavior/together.js`). The other four ride along for the desires to come.
- From core-api: `APTITUDES` (the five keys, in order), `APTITUDE_MOST` (4), `APTITUDE_AVERAGE` (2).
- PF2e reads them from its attribute modifiers (`FastFighting-PF2e/scripts/traits.js` `aptitudesOf`).

**Recovery checks rolled at the table (API 23).** A player's character dying as its turn began, its recovery check (a
death save) rolled by its player: told as the engine's own check is, a `recovery` event (`before`, `dying`, `better`,
`dead`, `stable`, `revived`, `text`) that the story tells from its recovery lines (`engine/live.js` `pcTurnEnd`,
`noteRecovery`). Systems count it their own way (one roll that settles it; several, as PF2e's dying steps and 5e's
three successes or failures), so what it came to is the system's to say, by the first that does:
- `readTurn` may give a `{type: "recovery", better, dead, stable, revived, text}` event read off the card: told as it
  says, the core's dying numbers beside it;
- `rules.recoveryRead(unit, {before, now})` (`{dying, status, stable}` each, the engine's before the sheet was read and
  after): `{better, dead, stable, revived, text}`, `null` for nothing to tell, `undefined` for the core's reading;
- the core's reading: dead, stable or up again as the sheet says, else a lower dying value better and a higher one
  worse; the sheet as it was, nothing told. PF2e's dying steps need nothing more.
The GMs' log gives the system's `text`, else what it came to (dying n, stabilized, dies).

#### Advantage reaches the system's roller (API 24)

The engine's own advantage on a roll it asks the system to make in a live battle goes with the request: `rollStrike`'s,
`rollSave`'s and `rollCheck`'s `advantage`, 1 advantage, -1 disadvantage, 0 neither (`battle-state.js` `systemRolled`;
`foundry/live-battle.js` `rollTurnStrike`, `checkOptions`; a player's own save or check on their screen hears it too).
Before, a strike's advantage was dropped on its way to the helper and saves and checks never carried it, so a 5e roll
came out straight. A system without advantage (PF2e) ignores it. And a recovery check its helper read off a card as
stable (`readTurn`'s `{type: "recovery", stable: true}`) leaves the engine's creature stable, where the sheet has no
such mark of its own (5e: three successes reset the tally).

The sheet's own state, for the system's rules (API 24): `rules.syncUnit(unit, state)`, where it's given, hears each
`readLiveState` a live battle reads (`engine/live.js` `syncFromSheets`, after the core's own fields), so the rules can
take up what only they keep (5e's death save successes and failures, which a player may roll at the table between
FastFighting's turns). Anything a helper's `readLiveState` returns beyond the core's fields reaches it there.

#### Estimates say so (API 25)

`rules.applyIwr(iwr, byType, target, ctx)` serves a blow that lands and the Statistics Engine's estimate of one alike:
what an action would deal a foe (`evaluate.js` `meanDamageVs`, kept for the batch in `prep.meanCache`), what a
condition's harm or an outcome's own damage is worth (`effects.js`). An estimate's `ctx` says `estimate: true` (a blow's
has no such field), so a system whose damage spends something of the target's (Daggerheart: an Armor Slot marked, Stress
marked) spends nothing for an estimate, and works the estimate out from what doesn't change in a fight, so the estimate
the batch keeps is the same whichever fight worked it out first. A system whose `applyIwr` changes nothing ignores it.

**A turn by one not in the fight (live battles).** One on its feet that isn't part of the fight (it hasn't noticed it,
has only just, or takes no side and has turned on no one) and does nothing in its turn logs `aside` (`simulator.js`
`noteAside`, after `noteIdle`), told from the story's `event.aside`, so the table sees its turn went by. Only with
`run.live`: a simulated fight tells no turn it doesn't take.

#### Table rolls: the engine's own dice, shown

Whenever FastFighting rolls dice itself for something a person would roll at the table, a live battle shows the roll in the chat as a real Foundry Roll. The Statistics Engine's own randoms (its choices, its model of morale and luck, a fight it imagines) stay hidden. A roll the system makes itself (`run.live.roll`: strike, save, check, use, damage, adjust, apply; `systemRolled`) is the system's card already and is never posted again.

- **The path** (`engine/table-rolls.js`, pure): a live battle's dice are rolled with a recording rng (`recordingRng`). It rolls exactly the dice the plain rng rolls, the same calls in the same order, and notes each die on a tape. A table roll claims the dice it rolled with what it was: `const at = diceAt(run)`, the dice, then `tableRoll(run, at, {by, target, kind, label, what, mod, total, dc, parts, multiplier})`. `kind` is attack, save, check, flat, damage, healing, recharge or other; `label` is the action's own name, else `what` names it from `FASTFIGHTING.Rolls.What`. A die is claimed once, so a roll inside another claims its own first. Unclaimed dice are never shown. `rollCheck` records itself (the roll's `by` or `roller`, `label`, `what`, `as` for a kind other than its `kind`, `target`; `quiet` for one only the Statistics Engine needs), and never a roll the system made (`rolled`). `rollHit` records a blow's damage, before resistances, its save's share as `multiplier`.
- **A helper's own dice:** its rules see the rng, so a helper records with `rng.mark?.()` and `rng.record?.(at, roll)`, needing no import. Optional chaining makes them a no-op in a simulation and with an older core. A system roll whose dice don't add up as a sum says how they show: `roll.shown` from `rules.roll` (as `split`: `[{dice, sign, roll, mod, total}]`, Ironsworn's action die against its challenge dice), or `each: true` (every die its own roll). The core shows a recovery check, persistent damage's end and `recoverBody` itself (`each`) when the helper doesn't record them.
- **When it records:** only a live battle's passes. `beginLive` (its surprise rolls: `takeRolls` after it) and every `nextDice` (each pass of `liveTurn` and `movedBeside`, `pcTurnBegin`, `reactNow` and `gmMoment` with no dice yet) start a fresh tray. A pass thrown away for a question goes with its run, and `liveTurn` returns its final pass's rolls (`rolls`). After any other step, `takeRolls(run)` hands them over. Simulations, plans, the Battle Vantage's odds, lookahead (`rethink` rolls on a throwaway rng) and restored copies (`restoreRun` keeps no rng) record nothing. A fate reroll's first try is kept, marked `rerolled`.
- **The system's own cards (API 20).** A helper may show a table roll as its system's card (`showTableRoll`): the core asks it for each roll, one card a roll in the order rolled, with the roller's and target's tokens, who sees it (`audience`, below), the core's words without the DC (`flavor`) and FastFighting's own flags for the message (so it's never read as a player's card, and Rewind deletes it). It returns its messages' ids, or null for the plain roll, which then gets a message of its own between them. Styling only: the dice are the engine's, exactly, and the engine's result stands whatever the system does with the card. PF2e shows attacks, saves, checks and flat checks as its check cards and damage and healing as its damage cards.
  - **Damage the engine rolled itself in a turn FastFighting plays** (a strike the system refused to roll, a save's or an auto's damage it didn't roll, riders, backlash and retorts, stray shots, reactions' harm and `areaBurst`, auras, maneuvers' damage, falls, collisions and hazardous ground, persistent and condition harm and afflictions the engine ticks, a fumble's): with `card` in `run.live.systemRolls`, the turn stops for it (`simulator.js` `engineCard`: `NeedsDecision` with `roll: "card"` and `table`, the rolls still waiting with the damage last) and the live side shows them all at once (`showTurnCard`), so the chat reads in order (the attack's card, then its damage's); every roll in `table` is marked `shown` and the damage's card kept as `card`. That card is then applied the system's way (`apply`, with a save's `multiplier`; a strike's with the `applies` of the reactions the system's application does), and the target takes what its sheet lost, as with the system's own rolls; one a reaction lessened otherwise takes the engine's sum. The card's dice are the ones the engine rolled in the pass that asked, and every pass after rolls the same, so the dice, replays and golden logs are unchanged. With **Play to the end** the live side answers null: the engine's sum, its rolls on the GMs' card. Without the hook (an older helper, another system), as before: a plain roll, the engine's sum.
  - A roll marked `shown` is never posted again, nor put on the GMs' card. A heal in a turn FastFighting plays is shown and applied the same way (API 21: **Heals and buffs named** above); anywhere else the engine's dice heal, and the system's card shows them.
- **Shown** (`foundry/table-rolls.js`): after a turn is written to the sheets, its rolls are posted, one message for each creature and audience, its token the speaker (with `showTableRoll`, one card a roll, the helper's where it shows it). Each roll becomes Die terms holding the engine's results (kept and discarded for advantage), the modifier, and the engine's total, so the tooltip and Dice So Nice show the real dice. Flavor comes from `FASTFIGHTING.Rolls`; the DC appears only on the GMs' messages. Who sees them (`rollAudience`): a player's character, everyone; a hidden token, an unseen or invisible creature, or one whose name is secret, the GMs; anyone else, the GM's own `core.messageMode` (gm, blind and self all go to every GM). The messages join the turn's own (`turn.messages`; a player's turn's reaction rolls `pc.rollCards`), so Rewind deletes them. With **Play to the end**, and for the aftermath, rolls gather instead on one GM-only card per battle (`battle.data.tally`): grouped by round and creature, folded in `<details>`, each roll an inline result. A rewound turn's rolls come off it (`untally`); Rewind This Encounter deletes it with the battle's cards.

#### Shared Foundry pieces (API 18)

What the helpers had each written for themselves is in the core, exported from `core-api.js`: from `foundry/sheet-tools.js`, `statusesOf`, `statusEntry` (the token palette as a list or a map), `toggleStatus` (with its undo), `undoRecord`, `payFrom`, `handOverItem` (with `statusesBefore: false`, API 20: its undo records keep no statuses from before, for a system whose conditions are items), `englishName`, `englishDescription` (up to `DESCRIPTION_MOST`), `plainText`, `numberSetting`, `idFromUuid` and `tokenIdIn`; from `i18n.js`, `englishWords`, `listWords`, `wordList` and `saysWord`; `partsOf` (trait-parts) and `sideAfter` (changes). In a live battle the core sets the token disposition of a creature that changes sides (undone with the turn), whatever the helper writes. An undo record may carry `systemOptions` (API 29): `{[system id]: options}`, passed under the system's id to the actor update that restores it (DCC's `{dcc: {abilityLogged: true}}`, so its ability log takes the restore as already logged); options under any other key are ignored.

### Senses, fate and what's already on a creature

- `spec.senses`: `{sight, lowlight, hearing, smell, feel, radar}`, how far each reaches in feet (`null`: no limit; `0`: it hasn't that sense; left out: the ordinary, which is sight across the field, hearing `rules.hearingFeet` (default 60), and none of the rest). Sort your system's senses into them, the farthest of each: seeing in the dark is `lowlight`; scent is `smell`; tech sensing is `radar`; any other sense of the creature's own (blindsight, tremorsense, lifesense, echolocation, thoughtsense ...) is `feel`. A creature with no eyes is `sight: 0`. Most systems have no use for smell or radar; leave them out. The scene's darkness comes in `options.darkness`.
- `spec.social.anyLanguage`: it understands and speaks every language (PF2e's constant tongues), so it can talk with anyone who has a language at all.
- `spec.resources.fate` and `spec.fateLabel`: points spent to keep someone from dying; `rules.avertDeath(u)` is the system's sure way out of one's own death, if it has one.
- `spec.mods`: bonuses already on it when the fight starts (one, or a list), but only what the system's own numbers don't already include.
- `rules.knockOut(u)`: a blow from someone who avoids killing, holding back.
- Lingering effects: `final.effects` lists what's still running; `commitChanges`' `options.effectSource(id)` finds the action that laid each, whose `effectRef` (the helper's own) says what to copy onto the creature.

### Dice, deeds, tables, checks and Luck in a CombatantSpec

See `behavior/riders.js`, `behavior/casting.js` and `behavior/luck.js`.
- On an action: `die` (its own die), `critOn`, `fumbleOn`, `deedDie` (rolled with the attack, added to the roll and the damage), `crit: {die, mod, rows}` (its crit table), `repeat` (a DamagePart: how many times the damage is rolled), `healDice` (so many of the target's own hit dice, `spec.hitDie`).
- A table row: `{lo, hi, damage, multiply, outcome, self, slay}` (`multiply`: the whole blow's damage times it, DCC's "double damage"). `spec.fumble`: the fumbler's table, `{die, mod, rows}`. `spec.critAgainst`: taken off crit rolls made against it by anyone but a player character.
- `spec.riders`: `[{id, label, when: "hit" | "miss", melee, ranged, weapon, resource, amount, uses, oncePerTurn, damage, critDouble, save, onSave, outcome, attackDie, tell}]`. Riders also take `vs` (only against creatures with one of these traits), `group` (one of a group per hit), `cost` (what it takes from the turn, on one's own turn: `{bonus: 1, slot: 1}`) and `dear` (a spell slot's level, which prices it).
- `spec.hazard` (a combatant): a trap, a haunt, a hazardous feature: `{once}` (a simple hazard fires once; a complex one each round), with `kind: "hazard"` and `untargetable: true`. It doesn't move, think or talk, nobody attacks it, it keeps no side in the fight, it fires at its side's enemies in its reach, and it waits out a standoff. It's set from the start (one outside the encounter counts while Bystanders is on); on the Neutral side it's taken as Hostile. Any system's token can be one: the GM marks it in the token's FastFighting tab, and the core makes it one (`applyHazard`).
- `spec.command` (the BattleSpec, beside `sides`): chains of command by group (a side; a neutral friend group is `"neutralParty#n"`): `[{id, role: "boss" | "leader" | "lieutenant", leadership: {brave, tacticalFloor, attack, ac}}]`, the head first. Without one, a side's `leaderId` leads it. `options.leaderInfluence` (0-100) and `options.bossInfluence` (×).
- `spec.deeds`: `[{id, label, melee, ranged, tiers: [{min, outcome}]}]` (an outcome with `self` lands on the one who did it; with `allies: feet`, on the friends that close: a rally).
- A check with tiers: `casting: {mod, faces, fumbleOn, lostOnFail, disapproval, label}`, `tiers: [{min, max, ...fields}]` (a save's `dc: "check"` is the check's total), `castChance`; the action's own fields are what a success most often does.
- An unarmed blow is a strike with the `unarmed` trait in its `traits` (PF2e's own), or `unarmed: true` from a helper whose system has no such trait: one with the Un-Mundane playstyle uses it only once it has no spell, power or weapon left (behavior/targeting.js `unarmedBlow`, `armedElse`).
- An action with `provokes: true` (API 29) lays its user open as it's taken: every foe in reach gets its opportunity strike, whatever `rules.opportunityOn` says (XCC's Wild Attack); the Statistics Engine counts what that would cost against what the action would do.
- An action with a `sequence` and `fumble: "all"` (API 29): its fumble table is rolled once, after it, and only when every attack of it fumbled (DCC's halfling fighting with two weapons); each attack still misses on its own fumble.
- `spec.boosts`: `[{pool, label, per, faces, allies, range, kinds, keep, recovers}]`, spending `spec.resources[pool]`.
- Legendary: `spec.legendary: {pool}` and actions with `legendary: cost` (taken between others' turns, never on its own); `spec.standFirm: {pool, label}` (a resource that turns a failed save that matters into a success).
- Mending: `spec.regen: {amount, stoppedBy: [damage types]}`, `spec.fastHealing: amount`, `spec.holdOn: {save, base, except: [damage types], notOnCrit, label}` (a save against base + the damage, to stay at 1 hit point).
- Saves: `spec.magicResistance`, `spec.saveAura: {bonus, range}`, `spec.evasion: "dex"` (with `rules.evasion(degree, save)` for a system's own version), `spec.saveUpgrades: [save types]`; an action counts as magical with a `rank`, `casting`, `spellId` or `magical`.
- Situational saves (`behavior/save-vs.js`): `spec.saveVs: [{bonus, type, saves, vs, all, not, from, advantage}]`, only what the sheet's own saves don't already include. `type` is `status`, `circumstance`, `item` or `untyped` (the default): of each kind only the best bonus and the worst penalty count, untyped ones add up. `saves`: the system's save keys it's for (left out: all). `vs` (any of them), `all` (every one) and `not` (none) are tags of the effect saved against: its `traits`, and the engine's own `magical`, `spell`, `area`, `damaging` and `inflicts:<condition key>`. `from`: creature traits of whoever set it off (`spec.creatureTraits`). `advantage: 1` (or -1) instead of a bonus, or with one: 5e Magic Resistance is `{advantage: 1, vs: ["magical"]}`. So put the system's own tags on every action as `traits` (PF2e: a spell's tradition from its spellcasting entry). An effect a hazard sets off also carries `hazard` and `trap` (API 29), for bonuses to saves against traps; and a hazard counts as having those creature traits for `from` (PF2e's Trap Finder, `origin:trait:trap`), one the GM marked in the token's tab too.
- Auras that make foes save (`behavior/auras.js`): `spec.auras: [{id, key, label, range, save: {type, dc, basic}, byDegree: [4 outcomes], damage, when: "enter" | "turnStart" | "both", immuneAfter: "save" | "success", immuneAll, immuneRounds, traits, needs: "sight" | "hearing" | "smell", foesOnly, magical}]`. It goes off at a foe that comes inside it (its own move, a push, its bearer's move) or starts its turn there, at most once a round; one inside as the fight begins saves at the start of its first turn. Its `traits` decide immunity (`rules.isImmune`, the aura as an action with `onSave: byDegree`) and situational saves; `immuneAfter` makes a creature immune once it has saved (any result, or a success) for `immuneRounds` (else the fight), to this bearer's or (`immuneAll`) every aura of its `key`. `foesOnly` is true unless said. Off the map, everyone is inside every aura. The Statistics Engine weighs walking into one to strike (`auraToll`). In a live battle the save is the system's (`systemRolled` "save", the aura's `id` as the action's) in a turn FastFighting plays and as a player's character ends a move (`movedBeside`); what it lays reaches the sheet with the change set, its damage as the engine's. A player's character starting its turn inside one is the table's: nothing is rolled for it. Events: `aura` (`actor` the bearer, `target` the one saving, `cause` "enter" or "turnStart", `immune`, `took`, `conditions`, `damage`).
- Martial: an action's `attacks` (how many it counts as for a multiple attack penalty), `sameMap` (a sequence all at the same penalty), `charge` (moves it includes before its Strike), `oncePerTurn`; a reaction `on: "allyHit"` (a friend within `range` is hit: `reduce` off its damage, `strike` back at the attacker in reach, or `redirect`: take the blow instead, against its own resistances; `tell` names its story line).
- Dice by who rolls, and a round of the system's own (API 10, Daggerheart): every roll names its roller (`options.roller`), and `rules.dieOf(roller, kind)` says which dice it rolls (a number, or the system's own name, which its `roll` and `distribution` read as `faces`; `roll` gets the roller too, for what the dice mean to it); a roll's `note` (the system's word on its dice) is logged with it and shown after its line; `rules.roundTurns(run, order)` gives who acts in a round, in order (a generator, so it can answer what happened: Daggerheart's spotlight); `rules.initRun(run)` sets up the system's own state for a fight; `rules.onDropped` gets the dice (`rng`), may leave `unit.fallNote` (logged with the fall) or `unit.lastStand: {turns, label}` (it fights on at 0 for so many of its turns, then dies: Blaze of Glory); an action's `resourceCost` (points a use takes) and `shared` (a key in run.sharedPools: a pool its side draws on, the GM's Fear); an undo record's `setting: {namespace, key, value}` (a world setting in the system's own namespace, put back).
- `spec.rarity` (0 common, 1 uncommon, 2 rare, 3 unique; for a system that rates creatures' rarity, PF2e): a rarer creature has a slight edge for command of a group outside the Friendly Team (leader, boss, lieutenant), enough to settle a near thing, never to beat a plainly better leader.
- An action with `uses` can come back: `recharge: {on, die}` (5e "Recharge 5–6": `{on: 5, die: 6}`, rolled at the start of its turn) or `cooldown: {n, faces}` (PF2e "can't use it again for 1d4 rounds": `{n: 1, faces: 4}`); with `rechargeOnCrit`, also whenever its user scores a critical hit with a Strike (PF2e Draconic Momentum).

### What an action needs first (`requires`)

See `behavior/requires.js`. An action may need something set up before it can be used: `action.requires` is an object whose entries must all hold, or a list of such objects, any one of which will do.
- `holding: true`: the target is one it holds (its grab, or a hold it laid: restrained, paralyzed, anything an Escape breaks). PF2e Constrict, Blood Drain.
- `target: [keys]`: the target has one of these core conditions; `unconscious` is also a creature down at 0 hit points, `grabbed` anyone's grab, `offGuard` however it's exposed, `restrained` tied up too. PF2e Drink Blood.
- `lastHit: true` or `{with: [ids]}`: its last action was a Strike that hit (with one of these Strikes); the target is the one it hit. PF2e Wicked Bite.
- `hits: {n, with: [ids]}`: its last n Strikes this turn hit the same foe (with these Strikes); the target is that foe. Once used, it needs n fresh hits. PF2e Rend.
- `self: [keys]` (it has one of these conditions; `hidden` includes invisible) and `shieldRaised: true`.

A Strike counts only on the creature's own turn, and "its last action" is the last thing it paid for from its turn (`Turn.acts` counts actions and Strides). A part of a multiattack built on another Strike names it in `from`, and counts as it for `with`. The engine checks a requirement wherever it decides what a creature can do: the options it weighs against a foe (`bestOptionVs`), an opening only another foe allows (the one it holds, the one it hit twice), and a hazard's routine. The Statistics Engine counts what an option sets up (`followUpWorth`): a Strike whose hit would meet a follow-up's requirement this turn, or grab the target for one that needs a hold, is worth its own damage plus `SETUP_SHARE` (half) of the follow-up's (its expected worth: a maneuver's, its control), times the chance it brings it about, when the turn has room for both. A maneuver that would grab or trip the target (a control action, even one that needs a hit first, as PF2e's Grab does; or a blow's maneuver rider, by its roll) sets up what needs that the same way. An action with a requirement isn't counted in a creature's typical threat or worth (`threatOf`, `typicalValue`).

### Setting characters up (API 11–14)

- A character's traits from many small parts (API 13): `traitsFromParts(base, parts, {from})` adds up `[{trait, n, why}]` from where the traits start (`PC_BASELINE`, the usual hero's, for a player character) and gives `{traits, reasons}`, each reason listing where it started and every part that moved it by its size ("player character 75, Will for its level +6, criminal -8"), as the planner's tooltip on the trait shows. The calculated answers ("Let this character decide") are worked out again when a character's traits change.
- What a character would do, from its system (API 14): `adapter.tacticHints(actor, spec, calc)` answers any tactics question, `consumables` too, as `answer` or `{value, why}` (why: the reason the GM sees, in the reader's language); anything else it answers (an `offer` or `expect`, once) is left out. They're kept with the character as what "Let this character decide" stands for, over the core's reading of its hidden scores.
- Setting a character up by itself (API 12): `adapter.playstyleHints(actor, spec)` (the playstyles its system says fit it: `{id: -1 to 1}`, from its class, ancestry, kind of creature, alignment, gear and role), `adapter.tacticHints(actor, spec, calc)` (the system's own answers to the tactics questions, where it knows better: `{key: answer}`), and `adapter.biography(actor)` (its biography and description as plain text for the keywords in [keywords/](keywords/README.md); or `{about, story, against}`: what's said of the character itself, counted in full; a story told about it, counted a little; and what it's against, counted the other way). Keywords move its traits wherever it's read, and its playstyles when it's set up. The core weighs these with what the spec's numbers and actions say (`engine/auto-playstyles.js`) and keeps what it worked out in `flags.fast-fighting.auto` (`foundry/auto-config.js`).
- What playstyle perks lean on, in any system (API 11): a buff can be a `guard` (a turn given to its own defense, 5e Dodge: the shield answer says how readily, where there is no shield to raise), a `setup` (one in a hurry, an Impatient one, doesn't stop for it), `leans: [behavior keys]` (likelier by those perks' strength: Hide leans on lowProfile, Secure an Advantage on hinders and exploitWeakness) and `check.against` (its roll against the foes' best defense of that kind, "perception" for Hide). One in a hurry doesn't stop to get clear of a foe beside it (it takes the free swings).
  - A skill (`theft`, `firstAid`, `sizeUp`, `doorWork`, an action's `check`) may name its die (`faces`: DCC's untrained d10); `iwr.exploit` (a kind of harm a foe guards less well, without a weakness's doubling: a weak spot to a Puzzle-Maniac).
  - `rules.pullsBlow(unit, action)`: one who spares the fallen knocks a foe out instead of killing it, where the system has a way to (5e a melee blow, PF2e any Strike, DCC a subduing weapon). Where a system says, one holding back pulls only those blows, and a blow it can't pull kills.
  - `rules.pullPenalty(unit, action)` (API 31): what a pulled blow costs on its attack roll (PF2e: −2 for a Strike without the nonlethal trait); the core adds it while the unit pulls its blows (battle-state.js `pullsThisRound`).
  - `rules.backlash` may return `to` (a friend put in harm's way takes the price instead: Ironsworn); `spec.caster` (a caster by the system's say, with no spell to show for it); `rules.afterRoll` sees heal checks (`kind: "heal"`); `rules.stealthInitiative` (a low-profile character rolls Stealth for initiative when it's better: PF2e's Avoid Notice).
  - API 19, surprise (the planner's Surprise, Follow System): `rules.surprise(run)` returns the system's own rule as the fight starts, `{by: [sides with surprise], round (a round 0 of theirs), stealthSides: [sides rolling Stealth for initiative], surprised: [unit ids losing their first turn, no reactions until then], disadvantage: [ids rolling initiative at a disadvantage], hidden: [ids starting hidden]}`, any of them, or null (no one). Without it, Follow System is greyed out. `rules.surpriseRound: false` (a system with no rounds: Ironsworn) gives the plan's own choices surprise without a round 0. The engine keeps it as `run.surprise` (`engine/behavior/surprise.js resolveSurprise`). core-api exports `SURPRISE`, `hiddenSides(run)` (sides with hidden tokens, an ambush) and `areEnemies`. A system whose surprise is a debuff rather than a lost turn (API 29) returns `caught` (creatures marked surprised that keep their turn) and `outcome` (what it costs, as an outcome: flat-footed, -2 AC), laid on the `caught` and the `surprised` through their first turn. `spec.alert` (API 29): never caught unready (DCC's "never surprised", 5e's Alert): never in `surprised`, `caught` or `disadvantage`, and it acts in a surprise round whatever its side.
  - A deed may carry `leans` and `guard` as a buff does (DCC: a trip leans on hinders, a rally on rally, a defensive maneuver as the shield answer says); `rules.optionWeight(run, unit, action, target, moves)` weighs an attack option the system's own way (DCC: one in a hurry would rather charge).
  - First aid (`spec.firstAid: {mod, skill, faces}` with `rules.firstAid` and `rules.firstAidDC`; `rules.canFirstAid(target)`: whether it can be tried on that one now) is given in the fight too, to a dying friend, as dear as `rules.firstAidCost`: a heal of its own kind (`firstAid: true`) beside the system's heals.
  - core-api.js also exports `applyOutcome`, `tauntProof`, `withoutTaunt`, `behaviorOf`, `isStanding` and `goadLuck`.

### System hooks (all optional, API 6)

- `rules.roll(rng, mod, dc, options)` and `rules.distribution(mod, dc, options)` for dice of its own (an action die against challenge dice).
- `rules.asRolled(rolled, mod, dc, options)`: a roll the system made itself in a live battle (`{degree, natural, total, dice}`), as the rules' own `roll` would have it with those dice, doing what that roll does (Daggerheart: Hope or Fear settled from its Duality Dice); null, or no hook, takes `{natural, total, degree}` as it stands. `rollCheck` calls it in place of rolling when `options.rolled` is given.
- `rules.adjustRoll(run, unit, roll, ctx)` after the dice are seen, `ctx.rolled` true where the system rolled them itself in a live battle (a card already shown: no luck or momentum to spend on it, but a flat check still stands) (a roll back with `said: {text, data}` is logged: burning momentum); `rules.afterRoll(run, unit, roll, ctx)` (who has the initiative); it gets the die's `faces`, and spell checks too (`kind: "cast"`).
- `rules.usable(run, unit, action, target)`; `rules.canTarget(run, attacker, target)`.
- `rules.backlash(run, attacker, target, action, degree)` and `rules.retort(run, saver, by, action, degree)` (what the attempt costs, or the blow back: `{label, damage}`; or a price the system paid itself, `{said}`).
- `rules.afterHarm(run, unit, amount, rng)` (a roll after being hurt); `rules.startTurn(run, unit)` (one report, or several `{unit, text, data}`).
- `rules.afterTalk(run, talker, target, roll, {aim, kind})` (what a pitch gives or costs); `rules.talkStrain` or `spec.social.strain` (`{pool, amount, crit, label, empty}`: a resource drained from whoever loses an exchange of words, the talker on a failure, its target on a success, `crit` on a critical (twice `amount` by default), and `empty`, an effect outcome laid on it when the pool runs dry; the creature's own wins; `rules.talkStrain` may be a function of the unit; `behavior/strain.js`).
- `rules.onFall(run, unit, {dead, source})` (someone down, beaten or killed: its friends' reaction, `[{unit, text, data}]`); `rules.onAllegiance(run, unit, {joined, against})` (someone taking a side mid-fight).
- `rules.applyIwr(iwr, byType, target, ctx)` gets the creature too (and, since API 20, what deals it: `ctx`, above).
- `rules.morale(run, unit)`: a morale rule of the system's own, for those it covers: `"hold"`, `"waver"` or `"rout"` (core-api's `MORALE`), or `{result, said}` to show the roll; null: FastFighting's.
- `rules.duel(run, caster, action)`: a spell duel (`{by, counter}`, someone answering a spell that worked with a spell of its own; the two checks compared, the higher standing, a tie neither: DCC).
- `rules.duelResult(run, {caster, by, action, counter, total, answer})` (API 34): the system reckons a duel's exchange itself (DCC with its book: momentum, counterspell power, phlogiston disturbance), given both totals (`answer` null when the answer's own check failed); null leaves it to the comparison above. It returns `{spell, counter, effects, label, disturbance}`: `spell` and `counter` each `{total, reflect}` (the total it goes on at, lower for one weakened: its tier there, nothing below its lowest; no total, it comes to nothing; `reflect`, it turns back on its own caster), `effects` `[{unitId, outcome, sourceId}]` laid on whoever it says (a duellist losing rounds), `label` the system's name for the result, `disturbance` a collision of magic (told as such). The answer goes on at once, out of its caster's turn: at the caster it answered (at its own caster, reflected), a buff or heal on its own caster; then the spell answered, at its own caster when reflected (simulator.js `castFor`, `duelAnswer`). Its rolls are the system's table rolls (`rng.mark`, `rng.record`). Logged as `duel` with `effect`, `spell` and `answered` (`undone`, `weakened`, `stands`, `reflected`).
- `rules.disengage(u)` may carry a `check` (`{mod, dc, dcMany}`: a roll to get clear, harder against several foes; missed, the free attacks come: XCC's acrobatics).
- `rules.strayShot(run, shooter, target, action)`: a missed shot into a melee (the friend it strays toward, attacked again; DCC).
- `spec.initiative.die`: an initiative die other than a d20 (DCC's d16 two-handing).
- A boost's `shared` key: a pool several creatures draw on together (`run.sharedPools`: DCC's Fleeting Luck).
- An undo record's `userId` and `userUpdate` (a player's own; its `flags.*` keys are put back).
- An adapter's `rewindFlagScopes` (API 36): flag scopes beyond FastFighting's and the system's that a Rewind puts back on an actor or a player (`["xcc"]`: XCC's Mojo, kept by the DCC helper under `flags.xcc`). Never `core`; plain scope names only (`make-it-so.js rewindScopes`).
- `spec.sharedHp` (a key: hit points several creatures share, falling together) and `social.steps` (successes to convince, the system's own number).
- An attack modifier's `score` (the score to roll outright: a progress roll, with `action.progressRoll`); `action.finish` (everything the target has left, on a hit).

### Reactions and summons in a CombatantSpec

See `behavior/responses.js` and `behavior/summons.js`.
- `rules.hearDC({feet, walls, talk})` (API 32): the DC to hear a sound so far off through so many walls that stop sound (shut doors among them): the din of a fight, or (`talk`) only raised voices, as a standoff has before a blow is struck. Null: it can't be heard. Bystanders noticing a fight (`simulator.js cueFrom`, from the awareness's `feet` and `walls`) and patrols hearing one (`senses.js hearDC`) use it; without it the core's own (`senses.js soundDC`: 8 + feet ÷ 15 + 6 a wall, talk +10, nothing past 300 ft). A system can also leave level out of the noticing check through `rules.modifiers.check`'s `purpose: "notice"`.
- `rules.talkFeet` (API 32): how far words carry in a fight, in feet (default 30, `talk.js TALK_FEET`). On a map a pitch reaches only one within it with no sound-stopping wall between (`talk.js inEarshot`).
- `rules.delay` (API 33): `{reactions}` where a creature may Delay (PF2e, `{reactions: false}`: none while it waits): as its turn begins, one that would do nothing useful now leaves the order and comes back after another's turn later in the round (a foe coming into its reach, a friend's bolstering, a standoff someone may break), its place in the order there from then on (`behavior/waiting.js`). In a live battle it moves on the tracker as the tracker moves on from it (`live-battle.js delayOnTracker`), and a Rewind of its turn puts it back (an undo record's `combatant.initiative`). Not with `rules.roundTurns`.
- `rules.ready` (API 33): `{cost, most}` where a creature may Ready (PF2e `{cost: {actions: 2}, most: 1}`): what's spare of a turn may go to readying its best everyday melee strike of `most` main-pool units at most, struck as a reaction, with the attack penalty it had when it readied, at the first foe whose move comes into its reach before its next turn (`answerMove`, a player's move too: `movedBeside`; asked in a live battle as `{reaction: {id: "readied"}, trigger: "foeEntersReach"}`). A system with it has a reaction a round even without opportunity strikes. Not with `rules.roundTurns`.
- `rules.delay` (API 34) may also give `reasons` (which of the core's own it waits for: `standoff`, `reach`, `aid`; all where it doesn't say, `[]` none) and `waitFor(run, u, later)`, a reason of the system's own, tried first (`{why, afterId, forId}` or null; `later`, those after it this round): DCC's caster waiting to answer a foe's spell, why `counter` (story `event.delayCounter`).
- `rules.delay.toEnd` (API 35): it always comes back at the round's end, whatever it waited for, its place last from then on (5e's homebrew Delay, a setting of the 5e helper's); on the tracker, below the lowest initiative.
- A notice check (`modifiers.check` with `purpose: "notice"`) says the sense it's by (API 34: `sense`: `sight`, `sound`, `smell`, `feel`, `radar` or `help`; a patrol hearing a fight, `sound`): DCC listens with Luck.
- `rules.minionCommand(minion, master)` (API 32): what a master pays at the start of its turn for its minion (`spec.flags.masterId`) to act on its next turn (PF2e: one action, the minion trait), or null where it acts on its own. A master commands each of its minions in the fight while it can pay; one not commanded since its last turn does nothing that turn; one whose master isn't in the fight, is down or can't act looks after itself. In a simulated fight a minion goes right after its master; in a live battle it keeps its place on the tracker, and one whose master a player runs acts (the command is given at the table). Summoned creatures are kept acting by `sustain` instead (`behavior/summons.js`); see `behavior/minions.js`.
- A `rules.minionCommand` cost may carry `once` (API 35), a key: one payment a turn commands every minion whose cost names that key (5e's Animate Dead and Create Undead: one bonus action for every creature the spell made).
- `spec.animalistic`: it fights as an animal does (`behavior/animal.js`: instinct, prey drive with bystanders as prey, retreat when hurt, a pack's nerve, no latch or lock). The helper's call: an animal or a beast by the system's own labels where it has them (PF2e's traits, 5e's beast type), else very low to middling intelligence with no language, and never a mindless one. Unset, an older helper's `flags.beast` counts the same.
- `spec.reactions`: `[{id, label, on, ...effects, ...filters, applies, resource, amount, uses, free, passive, tell}]`, the whole contract in `behavior/responses.js`'s header. `on` is a master trigger (or a list): `attacked`, `hit`, `missed`, `damaged`, `allyTargeted`, `allyHit`, `foeCasts` (`spell`), `wouldDrop`, `slain`, `allyMoves`, `foeApproaches`, `ownHit`. They share `rules.reactions(u)` a round with opportunity attacks (`free`: none spent).
  - **Effects at any moment** (`behavior/reaction-effects.js`, weighed and played in one place): `harm: {damage, save, move}` (at the one who set it off; a top-level `damage`, `save` and `move` are its harm), `afflict: {outcome, save, onSave: [critical failure, failure, success, critical success], traits}` (laid on it, by degree; with `onSave` and no save of its own, its harm's save, one roll for both), `boost` (an outcome on itself, until the end of its next turn unless it says longer), `heal` (damage parts), `recharge` (an action id or a list; `true`: each of its own that recharges), `strike` (`true`, its best everyday strike; or an action id, or a list), `step: feet`, `areaBurst: {damage, save, range}`. Moment-bound: `ac` (attacked, allyTargeted, hit), `halve` and `reduce` (hit; `reduce` on allyHit too), `redirect` (allyHit), `counter` (foeCasts), `stayUp` (wouldDrop).
  - **When:** what it does at `attacked` (beyond a bonus to AC) comes before the roll, and an attacker it fells or leaves unable to act never makes the attack; what answers `hit` and `allyHit` lands once the blow is done (a buff on itself at once, so a resistance counts against that blow); the rest as the moment comes.
  - **Filters:** `range`, `melee`, `ranged`, `physical`, `damageTypes` (only those types: what hurt it, or what it dealt), `crit` (a critical hit; on `missed`, a critical failure), `actions` (only those action ids: on `ownHit`, which of its own strikes), `needsShield`, `kin`, `byRange`.
  - **`ownHit`:** its own attack (a Strike, or a spell attack) hits; ctx `{target, action, crit, damage, types}`. The one it hit is the one its effects are at, and the one its `range` is measured to. A strike its answer makes sets off no `ownHit` of its own.
  - **Live battles:** a harm's damage is rolled and applied the system's way (`useAction` for the reaction's card, `rollDamage`, `applyDamageCard`, its id the reaction's), saves by `rollSave` (the action its id), a strike by `rollStrike`; a heal's amount is the engine's dice. What `afflict` lays and a `boost` reach the sheet with the turn's changes: conditions as conditions, and an effect the reaction laid finds the reaction as its source (`options.effectSource`), for the helper's `effectRef`. A recharge is the engine's to keep. Not played yet: a reaction to a player's own attack in the player's turn (its hit, its harm); there only moves (`movedBeside`) and opportunity strikes are answered.
  - **A foe moving in or out of its reach:** a reaction on `foeLeavesReach` or `foeMovesInReach` with `strike` (the strike it names, or its best) is struck as an opportunity strike is, at those moments, whether or not the system has opportunity strikes (`reactions.js` `threats`, `ownMoveStrike`); its uses are spent with it.
  - **Friends and moves:** a friend's reaction (`allyHit`, `allyTargeted`) answers a friend within `range`, and, with `byRange`, only with the foe that near too (PF2e's champion's reactions: both inside the aura). A reaction's strike back is `reaction-effects.js` `strikeBack`'s: its best melee strike with the foe in reach; with `strikeStep` (feet), after a Step that brings the foe into reach; with `strikeRanged`, a shot at a foe out of reach but in range (PF2e Nimble Reprisal). A friend's `reduce` with `applies` is done by the system's own application, as the target's own (`applyDamageCard` hears `{[applies]: {by: the friend's token}}`); its reaction is logged with `ally`, `took` and `struck`. `allyMoves`: a friend ends a move beside it (a square, diagonals too; or `range`); `foeApproaches`: a foe comes into its melee reach (or `range`) from outside it. Either may `strike` (its best melee strike, at a foe) or `step: feet` (a move of its own outside its turn, no parting blows, to the spot `bestStep` finds best: a foe to strike, flanked if it can, out of the reach of those who'd strike it); `kin: [creature traits]` answers only those with one (PF2e Goblin Scuttle: a goblin). In a live battle the same answers a player's character's move (`movedBeside`, played as a turn FastFighting plays is: the system rolls its strikes and saves), and a step is played on the map.
- A summoning: `{kind: "summon", creatures: [CombatantSpec], rounds, concentration, sustain: cost, sustainOrEnd}`; a creature with `untargetable` can't be attacked. `spec.size` (0 tiny … 5 gargantuan) and an action's `maxSize` are for the system's `isImmune` to compare.

### Buffs, debuffs and control in a CombatantSpec

See `scripts/engine/mods.js`, `behavior/effects.js`, `behavior/control.js` and `behavior/support.js`.
- An outcome with `armedBy: "kill" | "crit"` (API 29) does nothing until its bearer kills a foe or scores a critical hit with a blow; with `armedFrom: "source"`, until the one who laid it does (DCC's rally: "if the warrior slays its foe, allies gain +1"). `armEffects(run, u, what)` in effects.js.
- **An outcome** is `{conditions, mods, tempHp, mark, iwr, actionsNow, rounds, label, endsOnDamage, endsOnHarm, repeatSave: {type, dc}, onlyVs, self, uses, vs, vsFocus, boost, thisTurn, until, renew, resources, taunt, defy}`, all optional. `mods` holds `attack`, `ac`, `saves`, `checks`, `damage`, `speed`, `actions` (numbers), `bySave` and `byCheck` (`{key: n}`, one save or check alone), `attackDie` / `saveDie` / `checkDie` (signed faces: 4 is +1d4), and `adv`, `defAdv`, `saveAdv`, `checkAdv` (+1 or -1). The engine's own conditions are `CORE_CONDITIONS` (engine/conditions.js: prone, off guard, frightened, stunned and the rest, many with effects of their own); `controlled` and the other conditions toward someone are its `RELATIONS`.
  - A playstyle's taunt (behavior `taunt`, its share of `options.tauntLuck`): a control action with `goad` (`behavior/goad.js`), costing `rules.tauntCost` (a cost, or `(spec) => cost`; without one, `rules.talkCost`), its best of the `intimidate` and `deceive` pitches against `social.resist`, then the luck check. Behavior `tauntProof` (0-0.9): the chance any taunt is shrugged off as it lands.
  - Taunts: `taunt` (a desire level, 0 to 100, or `true` for 65, "driven"): while it lasts and its source stands, the bearer wants to go for the source at least that badly. It's one desire among its others (a stronger one of its own still wins; a taunter it can't reach wears it down) and blinds it like a stated one. `defy` (mods): what ignoring the taunt costs, on its rolls against anyone but the taunter (5e Compelled Duel `{adv: -1}`, PF2e Taunt `{attack: -1}`). The Statistics Engine weighs a taunt by the blows it draws off a friend, less the ones the taunter takes.
  - Edges (API 7): `uses` (spent by that many rolls it helps; a defense mark by attacks against it), `vs` (a creature id: only rolls against that one), `vsFocus` (laid on a friend: against whoever it's set on, its strongest hurt, talk or heal desire), `resources` (`{momentum: 2}`, through `rules.gainResource(unit, key, amount)`, weighed by `rules.resourceWorth(run, unit, key, amount)`). `rules.onOutcome(run, by, unit, outcome)` plays out anything else of the system's own (Ironsworn: in control).
- **A buff:** `{kind: "buff", outcome, targets: "self" | aura: feet | area: {targets}, range | reach, concentration, oncePerTurn, economy, tell}`. One that needs a roll to land: `check: {mod, dc, label}` and `onDegree: [critical failure, failure, success, critical success]` (an outcome or null each). `besideFoe: feet`: only for a friend whose foe is that close to the user (5e Help).
- **Sizing up a foe:** `spec.sizeUp: {mod, dc, label, boost, uses, anyFoe, missOutcome}` is the check a Lore-Collector makes (PF2e Recall Knowledge, 5e Study, Ironsworn Secure an Advantage); without `dc`, `rules.sizeUpDC(target)`, else the typical DC for its level. Without `sizeUp`, sizing up always works. What it pays off with: its rolls about `boost` times as likely to succeed (default 2.5), against that foe's sort (or, with `anyFoe`, anyone), for so many rolls (`uses`; default all of them while it lasts); `missOutcome` is what a miss costs, through `rules.onOutcome`.
- **Control or a debuff:** `{kind: "control", save: {type, dc, advantage} | check: {mod, against, attack} | bonus | auto: true, onSave | onHit | outcome, oncePerTarget, concentration, freeWhileHeld}`.

## Engine behavior in detail

[README.md](README.md#how-creatures-decide) gives the table's view of each behavior. This section adds the detail the engine works by.

### The planner and the plan

- A Secret token's team pills: a number no one else has is a team of its own. Who paused or un-paused the game while the planner was open has the last word; the planner closes for Go Live, and the game goes on once the fight is written.
- **Bystanders** check, on their own turn, whether they notice the fight now; once aware, they take their turns from the next round, as if they'd been in the encounter all along. An attack makes one aware at once.
- **The prediction** runs fight after fight until its time is up (`engine/run-budget.js`); a fight under way is always finished. Where the system's helper opens its rules to them, on background workers, several fights at once (**The planner's fights on background workers**); the swing factors' tests too.

### Personality and playstyles

- A player character starts at `PC_BASELINE` (bold, loyal, unselfish, a good head) and moves a little for each thing its helper reads (its stats, saves, class, background, feats). Biography keywords move each trait up to 15 points.
- **The trait budget** (`engine/trait-budget.js`): the four traits as the sliders have them (the sheet's reading and the GM's nudges) sum to `TRAIT_BUDGET` (250) at most, each still 0 to 100. Over it, the excess comes off the highest a point at a time, ties together; a raised slider (`withinBudget`'s `raised`) takes it off the highest of the others. `api.js` `keepTraitBudget` rounds a character's sheet reading (after its biography and trait rules) and trims it, marking the spec `overBudget`; `auto-config.js` then sets it up again once (`auto.budget`): its answers only, never its playstyles. The planner's sliders and `battle.js` (`fudgedTraits`, `sideTraits`) keep the GM's nudges within it (`budgetFudges`), as does **Side personality defaults**. Playstyle shifts, leadership and ADHD come after it.
- Pills weigh 1, 0.75, 0.55 and 0.4 by place (`ORDER_WEIGHTS`). **Stay mostly true** caps trait shifts at ±10 and any behavior that departs from the calculation at 10% of fights, and halves the desire guide. **Roleplaying is very important** doubles trait shifts, makes behaviors 1.8 times as likely, and weighs the desire guide 1.5 times (`engine/playstyles.js`).
- **Reluctance** (`behavior/reluctance.js`): the Consumables answers are worth 0.1 (I don't like to use consumables), 0.4 (Only when it really counts), 1 (When they're the right tool) and 1.3 (Consumables are here to get used); **I don't like to use spells that cost something** is 0.1 for spells with a resource or uses. A friend down and unstable, or itself under a quarter of its hit points, raises it to 0.9; for a playstyle that helps, a friend under half its hit points raises it to 0.6. The choice is made once a round for each kind of cost.
- **The wish table:** "Let this character decide" carries none of a wish, so a character nobody has answered for is as it was. With Stay mostly true, the talking wish is only a small nudge.
- **Auto playstyles** (`engine/auto-playstyles.js`) score each pill from three things: what the numbers and actions say (its traits, a player character's only where they differ from the usual hero's and at half weight, since its player says more about who it is; mindless or fearless; weapons close or far; its speed, and a melee reach beyond its size's; magic and specialties; healing and help for friends; ways to hamper a foe; a shield or good armor; skill at theft, lore and talk); the helper's `playstyleHints`; and biography keywords. A pill needs a fair score to be picked. They're picked once; after that they're the table's.
- **"Let this character decide"**: the helper's `tacticHints` answer first, with a reason; where it says nothing, the core reads the hidden scores and what the character can do; then its playstyles have their say. These are kept with the character and worked out again when missing or broken, when the core API has moved on, or when the character changes (a level gained, its traits, a new spell, the world's defaults). The GM sees each hidden score's sources on hover.
- **Playstyle details:**
  - Brawler: now and then a jeer (a taunt). Chicken: leading, takes its group with it when it runs. Diplomat: now and then pulls a killing blow, as a Moralist does. Fragile: once hurt, wants to heal itself if it can.
  - Impatient: each helper may add its own hurried moves (Daggerheart's Sprint, DCC's charge, Ironsworn's End the Fight).
  - Medic (behavior `medic`): heals a friend at three quarters of its hit points (`healing.js` `healScores`), its healing first on its agenda; offense that spends a pool its heals use is worth a tenth (`targeting.js`); bolsters before it attacks (`support.js`: the buff's baseline halved); gives a friend its own potion where the system marks it `administer` (PF2e's potions); keeps close to its friends (`prepare.js`). Set up by itself: healing of its own, the more ways the more.
  - DPS (behavior `dps`): its most damaging option, spending slots, focus and consumables freely (its suggested answers: Spend freely, Consumables are here to get used); control with no damage half as appealing, buffs and mending a friend who isn't down less; foes its blows hurt most (desire `hurt.softest`) and weaknesses; a melee blow that flanks for a sneak attack half as appealing again; sets up its blows when positioning; impatient with talk. Set up by itself: a best blow well above its level's typical, or a sneak attack.
  - Enabler (behavior `enable`): bolsters first (the buff's baseline down to 15%), then gives its friends an edge (control 2.5 times as appealing; a flank for a friend when positioning), heals only when no buff is worth giving (never a friend down), and fights last. Set up by itself: buffs for friends, ways to hamper a foe, a little for healing.
  - Kiter: keeps its distance (behavior `kite`, **Getting ready** below): a ranged one at the edge of its first range increment, beyond its foes' move and reach; a melee one in, a blow, and out again, a reach weapon that outreaches its foe first; falls back as foes close, toward its friends; goes for foes that can't follow (held, prone, slowed, slower, or struggling through the ground: desire `hurt.slow`). Cornered, it fights. Set up by itself: a fast shooter, or fast up close with a good defense; a reach beyond its size's leans it that way.
  - Lore-Collector: sizing up takes an action when the turn has one to spare; with one action a turn, the whole turn; in a standoff, most likely its whole first turn, watching while the talk waits. When it works (the system's check, if any), its next rolls against that foe are much likelier to succeed; never without paying for it. What it learns holds for every foe of the same sort (the same stat block, or the same name but for the number): one turn for three goblin warriors, and the payoff against any of them. Afterwards it still hits and talks to them a little better. It may tell its friends: its pill's chance times how minded it is (from even odds; more for the loyal, a tactical mind, and pills that lean on supporting friends: Enablers, People-Pleasers, those who'd lead; less for the selfish, the lazy, brawlers, mercenaries); its side's leader that readily, anyone else half as readily, unless it would rather talk than fight anyway. Telling is an action, now or first thing next turn, to every friend within a move of it (its speed) who understands it; they deal with that sort a little better too. Every Lore-Collector chance (sizing up, watching, sharing) shrinks further down its pills (×0.75, ×0.55, ×0.4).
  - Peacekeeper: everyone in a standoff with it, either side, loses patience half as fast; foes it talks round stand down (a truce, even mid-fight: never a surrender, a payoff or a rout).
  - People-Pleaser listens to its leader far more than most. Relentless: half a Skeptic's wariness of outsiders' words. Skeptic: the extra DC (up to 4) goes by the pill's place.
  - Tank: all of the taunt slider as its first pick. Un-Mundane talks less, unless its specialties make it better with words (a charm, an edge to its checks), and then it talks as much as anyone and reaches for them first.
  - Wants to Lead: now and then pins the biggest threat down; whether it actually leads is its group's chain of command.
  - Spoilers: the Instigator finds locking foes down, harassing and debuffing them up to 2.5 times as appealing; Puzzle-Maniac, Cruel, Wallflower and Wants to Lead lean that way a little.

### Desires and the agenda

- **Sources** (`behavior/desire.js`):
  - Tactics: each turn its tactical band weighs every foe it can reach (a Mastermind picks the healer to destroy, a Feral beast the nearest thing), every friend it could mend, whom it could talk round, whom it fears.
  - Stated desires: what, who and how badly; healing, bolstering and talking are offered only to those who can. Naming only creatures the player perceives on the battle map: on the scene it's looking at, with token vision, those within its sight; otherwise the encounter's combatants. With nobody to name, there are none to state.
  - The fight: simple minds go straight for whoever just hurt them; hit from afar while already trading blows, they keep at the one in front of them.
  - Its commander: every turn, the topmost thing its commander wants that it can actually do (a commander who'd heal a friend, followed by one who can't heal: its next wish) pulls on it by a share of its strength (15%, by its loyalty and playstyles; a boss's more), whatever the Leader's influence setting. On top of that, each turn it may take its commander's lead outright, as readily as Leader's influence, its loyalty and its playstyles allow (a boss's, by Boss's influence, more readily). Following, it takes the wish up in proportion to how strongly its commander wants it (most of its strength for a typical follower, all of it under a boss), so a leader's mild wish can lose to its own strong one, and its playstyle leans toward its commander's for the turn (about a third of the way for a typical follower, more under a boss: the commander's leanings, and quirks such as finishing off the fallen). With nobody able to lead, friends look after each other a little less, except when it comes to vengeance. A contrarian (an Instigator, a Wildcard) may lean away from its commander's wish instead.
  - The Friendly Team: the vote's wishes add Friendly vote's sway to what each friendly creature wants (on the 0 to 100 scale), and in that share of fights each uses the Friendly Team's answer to talking, spending and pulling out where it left its own to "Let this character decide". Other groups have no such wishes.
  - A friend asking for a buff: a character that wants to **be bolstered by** a friend asks, with no roll, if the two can understand each other (a language in common, and minds that follow it) and the friend is willing (the loyal gladly, the selfish grudgingly, helpers more than most, a contrarian never for the leader it defies). A friend with a buff to give then wants to bolster the asker as much as the asking times its willingness, and a single-target buff goes to the one it most wants to bolster. The story tells the call and the answer.
  - Its playstyles: each pill guides how it picks up desires, added up across up to four.
  - Focus fire (`behavior/focus.js`, the `focus` layer, worked out after the Friendly Team's wishes and before its commander's
    pull): once its side has hit a foe (`alreadyHit`: the foe's `harmedBy` has one of its team, itself too), each foe
    already hit gets more of its wish to hurt it, by its strength (`focusFire`: Tactical ÷ 100 from 40 if not dumb; 1
    for a pack hunter; plus its playstyles' `focus`; the world's Dampen non-friendly focus fire, `focusDampener`, takes
    up to half from those not on the friendly side), the most hurt the most. Capped at its strongest wish to hurt + 10,
    and below anything it's taunted into, told to want or held to by the GM. Below Tactical tier, `focusAgenda` (after
    `orderAgenda`) switches its top from a foe not hit to a stronger wish at one that is, with chance = strength. A
    commander that focuses fire sways its followers more for a foe already hit (`listen`, `leaderFocus`).
  - Keeping together (`behavior/together.js`, the `apart` layer, after `heed` and before `remember`): one smart and
    tactical enough (`keepsTogether`, `u.together` for the turn) wants less (`apartShare`) what it must move for that
    would leave it more than a Stride from every teammate and farther than it is now. It would rather not end a move
    bunched up beside a teammate unless the two flank their foe (`space.js` `crowdCost`): `battle-state.js` `spread`
    and `moveToShoot` take a spot in reach that isn't, if the same move gets there; `movesNow` counts moves as ever, so
    it costs nothing in the hot path. `prepare.js` `spotWorth` weighs both for a spot for later.
- **Thwarted desires fade:** a locked door that won't give, a target it can't reach, getting hurt on the way, being badly hurt with the target far off. It moves on when something gets too hard or too dangerous.
- **The agenda** (`orderAgenda`): each creature keeps its desires in an order, its top what it's working on, kept from turn to turn.
  - New desires go in at the bottom, unless something puts them higher. At the top: setting out to leave, whatever stops it on the way, a taunt, the GM's say, a fear past what its nerve bears. Second: leaving again once that's dealt with.
  - A good fit for what it likes to do goes in first or second, as does one that has come to fit since: a foe it was fighting fallen, for a Cruel one or one that finishes the fallen; whoever is at a friend it can reach this turn, for a protector (Tank, Martyr, Enabler, Moralist); a foe newly seen, for a damage-dealer; a friend down, for a healer (first for one that rescues the dying); itself past its potion threshold, first.
  - Everything climbs toward second each turn, past what it wants less, the faster the more intense (an obsession all the way at once).
  - Its mind jumps: the ADHD setting is the hidden chance each turn that the strongest thing it wants takes the top: twice as likely when that could be done this very turn, three times for the least thoughtful. Tactical creatures and better order their desires by what matters most, as a soldier would. A creature's own ADHD brings its Tactical down to 70% of what it is at 100%.
  - In the turn: a creature acting on impulse (instinctive or feral) works on its top first, then its second and third, the rest only once the top can't be done any more this turn. One that thinks has its top lead and goes about it in the order its tactics make sense of (a bonus-action heal before the blow). Healing is as urgent as the need: a friend down, as pressing as anything.
  - Desires it can't act on (whoever it would hurt nowhere to be found or out of reach, a friend to heal with no healing left, words for one who couldn't understand them) sink to the bottom and can't lead. Still impossible on its next turn, it gives the desire up, unless it's tactical or better: then it keeps it at the bottom until the chance comes. What the GM holds a creature to stays.

### Talking

- **Whom it talks to:** whoever it's likeliest to talk round, with the fewest steps left, worth the most out of the fight; a little more, the one its answer to **Who to pursue first** picks (the nearest, the weakest, the most dangerous, spellcasters and healers, whoever is attacking its friends).
- **Strain:** the talker pays when its pitch fails, the one it talks to when the pitch gets through, twice as much on a critical. Run dry, it's worn down as the system says (a condition, a penalty), and the story tells it.
- **Changing sides:** failing the switch luck roll, an enemy is talked into one of the other outcomes instead. Spells and abilities made for it (charm, dominate) turn a creature straight over until they end.
- **Standoffs:** before one breaks, a charismatic NPC leader may take one last turn to press the Friendly Team.
- **Only an argument:** the results count a collapse apart from "settled with words". The story tells who walked out and why.
- **Supply** (Ironsworn): what one loses (stolen, looted), the whole side has that much less of; Go Live lowers every friendly character's Supply, and every character the system shares it with. A foe's ground given is a mark of progress on its own track, the winners' reward.
- **A quarrel beside the standoff:** hurt or insulted by a neutral that seems to be with the other side, a creature may blame that side and break the standoff (a tactical mind mostly sees through it). Peacemakers on either side (those who can't abide violence) calm the quarrel at once: talking the neutral into letting it go, or the side's fighters into leaving the neutral be, until it hurts them again.

### Deals: bribes, extortion and scaring off

- **`engine/behavior/deals.js`.** Three desire kinds (`bribe`, `extort`, `scare`), made each turn by `dealWishes` in `thinkOver`, acted on in the turn's "deal" step (`decideDeal`, then `offerDeal`), and in a standoff by `dealNow`. A scare is an extortion that asks for nothing.
- **The check** goes through `systemRolled(run, u, "check", {purpose: "bribe" | "extort" | "scare", skill, deal})`, so a helper's `rollCheck` can make the system's own roll. `deal` is `{kind, ask, money, items: [{id, count}], wordless}`.
- **Rules:** `talkRange` (feet, 30 by default), `dealCost` (else `talkCost`, else the basic action), `wordlessIntimidation` (the check's penalty for a threat without words; unset, none without words), `languages: false` (the system doesn't track languages: the GM approves the conversation first).
- **Live hooks:** `run.live.dealAsk(run, request)` answers `{ask: "talkOk"}` (true/false) and `{ask: "answer"}` for a player's character ("accept"/"refuse"; null lets the engine decide).
- **Options:** `dropGoods: false` when the table can't show goods on the ground (no Item Piles, no system loot): goods then move at once.
- **Piles, meat and hunger** (`engine/behavior/forage.js`): `spec.piles` (the battle's, `loot-drop.js pilesOn` through `pileContents` and `isFood`) copied per run into `run.piles`; `spec.diet`, `spec.hunger`, `spec.cannibal`, `spec.hungry` (the GM's mark) and `spec.meat` from `foundry/food.js appetiteOf`. `initForage` rolls hunger (only where `spec.diet`: no new dice otherwise); `forageWishes` (in `thinkOver`) makes `u.forage`, shown as goals `pickUp` and `eat`; `forageTurn` plays the strongest when it beats the lead desire. What it took or ate is `u.foraged`, a change set's `foraged`, written by `writeForaged` (off the pile or the body, onto it or gone). `options.pcMeat`.
- **Reinforcements** (`engine/behavior/reinforce.js`): the planner's `options.reinforcements` (`{teamKey: {uuid, name, img, count}}`) read into CombatantSpecs once (`battle.js readReinforcements`, `sourceUuid` kept) and given the battle as `spec.reinforcements` (`{teamKey: {spec, count}}`), prepared in `prepareBattle` (`prep.reinforcements`). `run.reinforce[team] = {left, coming}`; the head calls on its turn (`reinforcementsWanted`, `callReinforcements`), the GM through `gmReinforce`; `arriveReinforcements` at `beginRound` makes units (`reinforcementOf`), remade by `restoreRun`. A live battle places them through the helper's `placeSummons`, one of the team standing in for the summoner (`placeReinforcements`).
- **Team stances** (`engine/behavior/stance.js`): each round's start (`beginRound`), a team's head takes a view of the fight (`run.stance[groupKey] = {kind: leave|save|harm|wait|prey, target, byId, odds, round}`), told as a `stance` log; members act on it on their turns (`stanceOf`: leave in `playFromHere` and `neutralTurn`, wait holds them back) and in `thinkOver` (`stanceWishes`). A new head decides again; `kind: "stay"` logs a recall. The Friendly Team only when `playsParty` (live: no player runs any of it; planner: `options.playersRun` false).
- **A player's deal** (`apps/deal-dialog.js`, `QUERIES.liveDeal` to the GM's browser): `targets` (whom the character perceives from where its token stands, by `senses.js` `perceives`, and the open names: `openNames`), `prepare` (again perceived, within `talkRange`, understood: or `{ok: false, reason}`), `rolled`. A creature whose name the players haven't learned is called by the story's name on every card they see, and in its gibberish.
- **The fallen's loot** (`foundry/loot-drop.js` `lootOnFall`, from `writeEach`): with Item Piles and `lootMode` "corpse", a creature's token is turned into a pile as it falls (`fell`, `died`) and back as it rises (`revived`), its token's look kept in the token flag `fallenPile`; the undo record is `{tokenUuid, itemPile: {made, was}}` (`revertItemPile`). A dead player's character gets a loot token on top of it with `goodsOf`'s copy of its things (Item Piles, else `dropValuables`, else the core's own pile: an actor of its type, flag `pile`); its uuid is `battle.data.remains[id]`. The engine's `options.remains` (`leavesRemains`: not "none", and the helper has `goodsOf` and `putGoods`) lets robbers go for it (`theft.js` `leftRemains`, `lootable`); such a concession has `from: "remains"` and is committed off the loot token. `isPile` keeps piles out of `gatherRoster`.
- **Tolls** (`mayToll`, `tollPrice`, `payToll`, `teamWealth`, `payers`; `TEAM_TOLL`): kind `toll`, the asker leaves (`quitFight` with `whole` for a leader; `goneAtOnce` for a player's character), paid at once by the target's team.
- **Team cash:** `spec.purses` (by group key, in the smallest coin; the planner's `options.purses`, in the system's main coin: a helper's `mainCoin()`, API 26). Members share `unit.purse`; `remaining()` gives `own`, `purse` and `money` (both). A payment's `purse` part (with `purseKey`) comes off no sheet: a live battle puts it on the receiver through `putGoods({money})`. The purse is pictured split as the fight starts (`purse.shares`, `totalShares`: battle-state.js `purseShares`, from the command chain then: 1 each, a lieutenant 2, a leader 4, a boss 4 × `options.bossInfluence`), and promotions and demotions later change no one's share. A member that dies leaves its shares of what's still in the purse on its body (talk.js `dropShare`: down for a single share, up for the rest; `unit.purseDrop`, settled at each turn's end and the fight's, logged as `purseDrop`), and the purse has that much less (`purseLeft`). A live battle's change set carries `purseDrop`, put on the dead creature's sheet through `putGoods({money})`, there for its pile. The planner's **Loot** (`aggregate.js` `lootFound`, `money.looted`): after a party win, the `worth` (its coin, gear and `purseDrop`) of each foe out of it and anyone else's body, if `seen` (`u.partySaw`, `senses.js` `noteSeen`: perceived by a standing PC, or met in blows or words; marked at each turn's end and the fight's, the same mark that lets the live story name it). Spoils is only what's handed or taken.
- **Goods** are the giver's concessions (`how: "bribe" | "extort"`, `count`, `drop: {id, x, y}` when dropped, `picked` once picked up). The taker's `fetch` is the drop it walks to.
- **Wanting no part of it** (`shunsFight`, `seesFight`, `reactionBribe`): a timid NPC taking no side leaves when it sees a fight (`neutralTurn`); attacked, it spends a reaction (where `reactionsPerRound` gives it one) on a bribe to be spared, made in `executeOffense` before the blow (`deal` logged with `reaction: true`).
- **Bought over** (`turnChance`, `turnOver`): a bribe taken may turn its target with talking's outcomes (`applySway`: an enemy stands aside, one taking no side joins), logged as a `sway`.
- **Log types:** `deal` (`answer`: accept, refuse, offended, unpaid, unheard; `by`: check, player, gm), `quit`, `quitCall`, `dropGoods`, `pickUp`, `dishonor`, and `offMap` with `walkedAway`.
- **Live** (`foundry/live-battle.js`, its Deals section):
  - `answerDeal`: a creature's deal with a player's character (`dealAsk` "answer") asks its owners on a card (`askPlayerDeal`, `QUERIES.liveDealAnswer`), then the GM's review (`reviewDeal`).
  - `dealTurnCard`: a player's turn brings the deal card (`dealOpen`), removed by the next card.
  - `apps/deal-dialog.js`: the player's dialog. It asks the GM's browser (`QUERIES.liveDeal`, `answerDealRequest`): "prepare" checks the turn, the goods and the language (`gibberish`), and gives the DC; "rolled" gets the answer, the review, and holds a `deal` fact with the turn (`engine/live.js applyFact` → `closeDeal`).
  - `apps/deal-review.js`: the review window, reopened by its GM card and the Battle Vantage (`waitingDeals`, `openDealReview`).
  - `shortOnSheet`: goods the payer no longer has on its sheet don't move.
  - A `dishonor` event is a GM-only card (`tellNew`).
  - Helper hooks for it: `skillsOf`, `giveables` (API 26), and `rollCheck` with a deal's purpose and the player's `skill`.

### Groups and taking no side

- A hostile group's leader is the one you pick, if it's in that group; otherwise the group's best. A neutral's kind: 5e its type and subtype; PF2e its ancestry, else its creature types; Ironsworn what the foe is. Different friend groups are nothing to each other.
- **The lean** (`behavior/neutral.js`) nudges what neutrals want as a leader's word does: the favored side's members safer and less to hurt, their foes a little more, by a share of the lean's strength and as loyal as each is (less for the selfish), on top of everything else. Leaning isn't guarding. What they feel for that side is the lean in full: watching them hurt, they take it personally, they spare them while they talk, and joining them appeals. The underdog's members change as the fight goes. A friend group pulls toward keeping its own safe the same way. An enemy who stands aside still leans a little toward its old friends, more the more loyal it is. The lean wears down, or ends, either way round.
- **Crossed:** seeing someone hurt or hinder a creature it wants safe, or heal or bolster one it badly wants hurt, builds a grievance against the doer's side, faster the more it cares and the worse the harm; enough of it offends.
- **Words first:** the offender's side can talk it round, or it can talk the offender into making amends (an apology).
- **Won over:** against its lean too. Talkers weigh what joining would mean to it: a pitch that gives it what it wants (keeping someone safe, a chance at someone it wants hurt) is easier and quicker, so one already leaning their way doesn't take much; one that betrays what it wants is harder and slower. Go Live changes a creature that stood aside to Neutral.
- **Who knows:** only a tactical talker knows a neutral could be won over. A feral creature's attack on one offends it and ends any lean toward the attacker's side. One who always tries words first (a Diplomat, "Talk first", "Always talk") talks to a neutral it takes for a foe, and may win it over by accident; a desire to talk to it (stated, or its leader's) does the same.
- **Getting involved:** the odds rise with how well it likes the side (the strength of its lean) and how much that side looks like winning (its standing members' hit points against its enemies'); the bold and the talkers get involved more readily. Involved:
  - talking the side it likes least into running or standing down; in a standoff that settles it for the side it leans toward, as if that side had done the talking. Leaning toward the Friendly Team's enemies, it talks the Friendly Team down instead (a player character can only back off);
  - a neutral in the encounter from the start is aware of the fight at once; one that isn't has to notice it first.
- **Can't abide violence:** it talks whoever it's likeliest to move, either side.
- **Keeping the peace:** while a neutral is having words with a side, that side's smart members (Tactical and up) hold off hurting it or anyone it wants safe, unless the talk is going against them anyway (nobody left who can talk to it, or it's nearly out of patience). Smart creatures likewise rarely break an opening standoff unless their side is losing the talk.
- **Not one for killing:** a character whose answer to foes who fall leans to avoiding killing ("Spare them: I avoid killing" most), seeing an enemy that was talked out of the fight, wants to talk to it again, just under whatever is most on its mind (unless it already wants to talk to it more): into leaving, or onto its side, as its playstyle leans (Peacekeepers, Diplomats, Moralists, People-Pleasers, Chickens, Wallflowers and the like would rather it left). Those who command their group and talkers among them want it more, look for the chance with any neutral they see, and always try to send it away: one less fighter on the field is safer than one more, even a friendly one.
- Those who take no side don't keep a fight going.

### Command, morale and leaving

- **Leadership** ranks by the best social or warfare skill, plus commanding features (the system's `detectLeaders`).
- **Chains of command** (`foundry/command-pick.js`): outside the Friendly Team, the system's ranking of who leads (social and warfare skills, a commander's class, rallying abilities) counts double, and how bossy each member is sways it (its playstyles, Wants to Lead above all, then Instigator and Cruel, while People-Pleaser, Wallflower and Chicken hold back; its Brave and Tactical). A group of one has nobody to command. Tokens joining the fight or moving between groups reshuffle nothing. A lieutenant leads as a leader, never as a boss. Nobody able to lead: the group is leaderless.
- **Bosses:** in a standoff, talked round like anyone (their group stands down with them); in a fight, only badly hurt (under a quarter of their hit points), when they surrender. Never into leaving.
- **Scheming:** a Wants to Lead character not in command broods on a quarter of its turns as its first pick, less further down (×0.75, ×0.55, ×0.4), more with roleplay, at most a tenth staying true. With a treacherous streak, it wonders how to be rid of its commander (the story says so), refuses its leaders any help that turn (no healing, bolstering, guarding, following, or answering their requests), and is far easier to talk into changing sides (2 steps fewer, the DC 4 lower, the switch far likelier, the switch luck 20 higher).
- **Morale** (`behavior/morale.js`): losses, wounds, a fallen leader or master, bad odds, and friends seen running, all against Brave.
- **Fear:** being afraid wears on its nerve, more so for the less brave; a fear made worse past what its nerve bears gives it a wish of its own to get away. Both follow the fear as the system has it: lowered or lapsed, less or none.
- **Running together:** seen running, whatever sent it (its nerve, a terror, a retreat rule, someone's words, a spell such as fleeing or turned), a creature shakes every friend in its group, who wonders at its next turn whether to run too. One of its leaders running hits harder, the more so one prone to running (a Chicken above all; Fragile, Mercenary, Lazy, Wallflower). A group with nobody able to lead takes it harder still; one whose commander stands steady takes it easier (a boss's presence much easier, by Boss's influence).
- **Calling a retreat:** whenever one decides to run, it first tries to take its group with it. Its commander decides: one who commands calls it itself (a pack runs with its leader); anyone else has to talk its commander into it, which works the more shaken the commander is and the better the case (a lieutenant's word, a way with words). Refusing, the commander orders it to hold, and it does as readily as it would take its commander's lead. Called, the group falls back together, each member as readily as it would take its commander's lead, more when shaken, much more under a leader prone to running. With nobody to lead it, a group runs together more readily still. Never the fearless, nor a player character. The story tells who calls the retreat and who goes.
- **Rallying:** seeing friends run or waver, its commander (or one brave and loyal enough with the voice for it; Wants to Lead and Martyrs more readily) may spend an action holding the rest together: those within 60 feet are steadier this round and the next (less stress, slower to answer a call to retreat) and may shake off wavering. A commander's rally carries more, by Leader's influence; a boss's by Boss's influence too.
- **Leaving the field** (`behavior/leaving.js`): a creature that runs, is talked into leaving, or falls back with its group drops its quarrel with whoever talked it into leaving (with all its foes, when its own nerve sent it), wants nothing so much as to be gone, goes as fast as it can, and breaks free of a grab first. Two whole turns given to leaving count as gone even if the walls shut it in. In a live battle its token is hidden and put in the scene's first square, and it comes off the tracker when the tracker moves on; with fled tokens left in place, it stays where it went.
  - Leaving creature keeps going: one whose answers and playstyles lean to going (retreating once hurt, a Chicken) gets all of the setting's share; one who'd rather stay (Fight to the end, the brave, Vengeful or Relentless when struck, a Diplomat when spoken to) gets less, never under 70% of it.
  - Stopped, what stopped it becomes its strongest desire, leaving its second, and it needs two whole turns again. Each blow and each word is a new check. Every stop weakens its wish to leave, more for one who'd rather stay, and a creature stopped often enough forgets leaving and is back in the fight. The GM sees each check on the GM-only card.
  - A creature still on its way when the fight ends has gone. Without a map (no positions), it's gone at once.
- **Of its own accord** (`behavior/flight.js`, after the morale check): life over loot (a hostile NPC leaderless or led by one who'd rather run) and off with the prize (an NPC holding something taken this fight). Alone (`flee`, no retreat called); never with morale off or for one standing its ground.
- **"Fight to the end"** applies when running would be its own choice (its nerve breaks, a terror is close by, a retreat it planned), and less for answers that lean less that way. Talked out of the fight, it mostly gives up where it stands instead of running.

### The fallen, holds and troubles

- **Tie them up** uses whatever's to hand (a strap, a rope, their own belt). Peacekeepers, Moralists, Diplomats, Wants to Lead, Mercenaries, Lore-Collectors and Redeem-Seekers lean that way.
- **Breaking free** (`behavior/holds.js`): a prisoner's struggle is the only thing it can do on its turn; loose, it's back in the fight from its next turn. Anyone held (grabbed, or by a condition its system says an action can break: a web, a net) wants to break free, the more so with no foe beside it to fight where it stands. A friend tied up (or held by what a friend can break) is freed by whoever wants to, an action beside them: loyal friends most, and Martyrs, Moralists, Enablers and Wants to Lead more than most (the Lazy less). Each helper can say how it's done in its system: its own Escape, the check, its DC, what it costs.
- **Bearing it, or being rid of it** (`behavior/troubles.js`): what holds or hurts a creature (tied up, grabbed, on fire, bleeding, prone, and whatever its system says an action ends) bothers it as much as it hurts, the fearful most, Chickens and the Fragile more, Martyrs, Tanks and the Relentless less. Tied up with a spell that needs no hands and a foe in range, a bold one may cast from its bonds rather than struggle. The selfless bear it as the setting says, the more self-serving or calculating the less.
- **Under control:** moved to another side by the GM (the Battle Vantage), a creature's wants and everyone's toward it are worked out again, and its new side's leader is its leader.
- **Rob them:** a fallen foe's purse comes off whole (a share, where its side pools its money), else something it carries, else (a creature's) what it was holding, an action beside it. Thieves and Mercenaries lean that way, the Cruel a little; Moralists and Peacekeepers lean away.
- **Fallen PCs:** a creature that turns away from a PC gives everything it wanted of that PC to the next foe it would pick. Fate rerolls a blow (a hit may become a miss), a save or a recovery check that would kill; PF2e Heroic Recovery spends all of one's Hero Points.
- **Theft** (`behavior/theft.js`): alone means no friends within 30 ft, or the two of them more than one ordinary move from everyone else. Stealing openly, the thief feints first (it must hit, for no damage), then makes the stealing test. Thieves rob those who take no side too; caught by one, it turns on the thief's side.

### Taunts and traps

- **Taunting** (`behavior/goad.js`): a taunt is as dear as the system says (PF2e one action, 5e an action, DCC an action die, Ironsworn a move). Its roll counts anything the taunter has learned about the foe and any edge it has. Taken hold, the foe wants the taunter ("driven"; on a critical success, past anything but an obsession) until the end of its next turn. It takes a voice, and a foe with a mind to rile. The simulation taunts when drawing a foe off a friend spares more than the taunter takes (a Tank minds the blows half as much). A taunter pill further down counts less (×0.75, ×0.55, ×0.4), and so does a hard-to-taunt one. Shrugging off works against a playstyle's taunt or a game system's.
- **Trap avoiders** (`behavior/traps.js`): a watchful pill further down counts less (×0.75, ×0.55, ×0.4). Moving, a creature goes around the hazards it knows or, with no way around, stops short. When what it's after is in a hazard's reach: driven or more, it goes in; merely wanting it, it doesn't; determined, it might, the likelier the more it wants it. Starting its turn in a hazard's reach with nobody beside it, it steps out first. The story says which.

### Buffs, senses and doors

- **Buffs:** one friend, several, or everyone in an aura. A save at the end of each turn can shake some off (Hold Person); damage ends some (sleep). With concentration, one spell at a time, and a hard knock or being taken out ends it. A buff's worth counts the rounds it will matter; late in a won fight, nobody bothers. A charm or domination ends when it runs out, on a save, when the holder loses concentration or falls, or when the holder's side harms a charmed one; its friends are reluctant to cut it down, and the story still counts it as one of its own. Edges: PF2e Aid is a check against DC 15 for +1 to a friend's next roll, more on a critical success, -1 on a critical failure; Friends gives advantage on words to one creature; Sure Strike; Ironsworn's Aid Your Ally gives +1 on the next move, or momentum. Laid on a friend, an edge counts against whoever that friend is set on (the foe it wants to hurt or talk round, or the friend it wants to tend), and it's spent by the roll it helps; bonuses to checks count for talkers and healers, so a talker is worth guiding before it speaks. The story: *"Akra lifts Bless over the group: Akra, Zanna and Randal, emboldened."* Dodge, Reckless Attack and Action Surge get lines of their own.
- **Senses** (`behavior/senses.js`): a foe it can't perceive looks unhurt, and it doesn't go after the fallen it can't make out. In a crisis, twice the range, no line of sight or light needed (a smell still doesn't pass a wall). The din of a fight carries farther than 60 feet, harder to make out with distance and walls (`HEAR`, `hearDC`, shared by the Foundry side's `computeAwareness`); bystanders notice it seen, picked up on radar, felt, smelled or heard, and a patrol hears it (**Patrolling**). One it found with a Seek isn't hidden from it (`hiddenFrom`), until it hides again.
- **Doors** (`behavior/doors.js`): more patience with a locked door when there's nobody else to fight; giving up turns the desire to something else. The system's door has its defense, hit points, DCs and its own damage rules (PF2e hardness, a 5e damage threshold).

### Getting ready

`engine/gear.js` and `behavior/prepare.js`; the numbers in [STATS_AND_FORMULAS_README](STATS_AND_FORMULAS_README.md#getting-ready-draws-reloads-and-a-turn-for-the-next).
- **Its weapon not in hand or not loaded:** a turn that can't pay for its best option draws or reloads it, for the
  next. A creature that can pay for it all does it in one (draw, Reload, shot).
- **Healing it can't give this turn** (its top desire): it goes to the friend, as far as the heal needs, or gets a
  potion out; the rest of the turn goes to what else it wants.
- **What's spare after its main actions** (actions it found nothing better for, 5e's movement after its action, a PF2e
  third action a Strike at the full penalty isn't worth): its gear for next turn, a potion, standing up, a raised
  shield, or a better spot to end on: where it can strike or heal next turn, a flanking spot, cover for a hider,
  between its foes and the friends a protector guards, out of reach and behind its friends for the timid. It never
  takes the place of an attack, a heal or a step it's already taking.
- **How it's weighed:** what it enables next turn, discounted, as likely as it is to matter; a spot also by the harm it
  spares, as much as the creature minds being hit (the selfish, the timid, the badly hurt, shooters and kiters more,
  protectors less), less the reactions moving there provokes. The same reckoning as `followUpWorth`'s.
- **Lazy creatures still slack** now and then; being unable to act directly is no reason to idle any more. One that
  knows of no foe patrols (**Patrolling**).
- **Waiting for the moment** (`behavior/waiting.js`, where the system has `rules.delay` and `rules.ready`): a turn
  it would waste it Delays (for a foe to come, a friend's help, a standoff to break), checked as its turn begins, before
  slacking; a turn it can't use the rest of goes to a readied strike, one of the spare steps, as does the turn of one
  its team's head holds back.

### Patrolling

`behavior/patrol.js`; the numbers in [STATS_AND_FORMULAS_README](STATS_AND_FORMULAS_README.md#patrolling-cues-and-seek).
- **When:** its turn's main loop found no foe to go for (`simulator.js` `playFromHere`: `lacked`), and with what's left
  after any step for later (`spareTurn`), it patrols if it's in the fight (no standoff holding), standing and able to
  act, not leaving or held (a grab, its bonds, a hold it would break), not a hazard or summoned, and knows of no foe on
  its feet (`knowsAFoe`: none in its senses, seen before or come to blows with, a standoff holding them off or not). It
  replaces the idle turn ("lazy" with no `chose`). A Lazy one may still slack first (`slacksOff`). Whatever it finds,
  it goes back to fighting at once with what's left of its turn (`fightOn` again).
- **How** (`patrolMode`): its pills' `patrol` (each a vote as heavy as its place: `playstyles.js` `patrolStyle`), else
  an animal roams and anyone else watches; tactics' "Hunt down enemies nearby" makes a watcher a patroller, "Stay with
  the fight" holds it where it stands (a hider still hides). An animal with a patroller's or a watcher's pills roams.

| Playstyle | patrol | Why |
|---|---|---|
| Wants to Lead | spread | Leads the sweep, covering ground for its people. |
| Tank | spread | A guard: takes the ground in front of its friends. |
| Brawler, Impatient, Instigator | spread | Looking for a fight, and won't wait for one. |
| Lore-Collector, Puzzle-Maniac | spread | Curious: goes to see. |
| Vengeful, Relentless, Cruel, Redeem-Seeker | spread | Hunting its foe, or out to prove itself. |
| Wildcard | spread | Restless: it wanders off. |
| Medic, Enabler, Martyr, Moralist, People-Pleaser, Peacekeeper | near | Stays by the friends it heals, bolsters, shields or follows. |
| Fragile, Lazy, Diplomat | hold | Holds back: won't walk into trouble (Fragile), can't be bothered (Lazy), would rather wait to talk (Diplomat). |
| Chicken, Wallflower | hide | Keeps out of sight: stays put, or hides. |
| DPS, Kiter, Skeptic, Mercenary, Thief, Un-Mundane | (none) | Nothing in it says either way: its nature decides (an animal roams, anyone else watches). |

  - `roam` (an animal, taken to be hungry): toward the strongest cue, else it wanders, out from where it began by 20
    feet and 15 more each turn it finds nothing (to 120); a pack keeps within 30 feet of each other, and goes where a
    packmate's cue leads.
  - `spread` (a patroller): toward a cue, else out to 20 to 30 feet from its teammates (its own side or friend group:
    `alliesOf`, not every friendly creature), where it hasn't searched.
  - `near`: stays within 15 feet of its teammates, searching from there, going where they go (alone, as a watcher).
  - `watch`: toward a cue (the din of a fight it hears), else it searches from where it stands.
  - `hold`: searches from where it stands, going nowhere. `hide`: hides where it can (its Hide, a buff that hides it,
    where the system lets it use it) and keeps hidden; else it stays put and searches.
- **Cues** (`cueOf`, once a turn), the strongest first, each a creature it heads for the engine's way (its approach,
  the way round walls, a door worked as any is): a foe's scent it can follow (within twice its smell, along the way
  there); the din of a fight it hears (anyone in a blow this round or last, the easiest to hear by `hearDC`, its
  Perception against that DC: the Statistics Engine's own check, never shown); a foe its teammates have in view; for a
  pack animal, a packmate's cue.
- **Seek** (`seek`): what `rules.seek` says (above), else the core's: the basic action, its Perception against the
  Stealth DC of each foe in the area that's hidden from it or out of its senses, walls blocking as they block sight
  (`inArea`). One roll against the hardest of their DCs (nobody there: the typical DC for its level), each found by its
  own degree: known to it (`seenFoes`), and no longer hidden from it (`foundBy`; an invisible one stays hidden). The
  roll is the system's in a live battle (`systemRolled`, purpose `seek`), else a table roll. A spot searched this round
  or last (within 15 feet) isn't searched again: three actions are Seek, Stride, Seek from a fresh spot, and Stride,
  Seek, Stride from one searched already; toward a cue, Strides, and a Seek with its last action. `rules.afterRoll`
  hears it (PF2e: a hidden seeker gives itself away).
- **Its moves** to a spot count the harm the foes it knows of could do it there, and the blows of those whose reach it
  leaves, as a spot for later is weighed (`prepare.js` `walkRisk`). Toward a cue there's nothing to count: it heads
  for one only while it knows of no foe.
- **Fidgeting** (`fidget`): a turn it spent nothing of at all (`turn.acts` none, its movement untouched), able to act
  and in the fight: chance = the ADHD setting's share × (0.5 + its own ADHD's share). A step aside to a free spot
  beside it (no foe it knows of near, paid for as any move), or a look elsewhere (where its next Seek's cone looks).
- **Told:** `patrol` once a turn (the story tells it once, and again when it goes about it differently or after a round
  without it), its moves by it (`patrol: true`), a Seek that finds someone always and one that finds nothing once with a
  told patrol, and `fidget`; the Statistician's lines `Patrol`, `Seek`, `Fidget`, `MoveSearch` and `MoveStep`. The Battle Vantage
  marks one that patrolled on its last turn "patrolling" (it moved) or "searching" (`patrolNow`, a `status` mark).

### Combat details

- **Extras on a hit:** the emptier the pool, the more a use has to be worth; conservers want more, those going all out less. A die can mend a close miss.
- **DCC:** a deed declared before the attack (trip, blind, disarm, a defensive stance) happens on a hit if the deed die shows enough; a crit rolls on the attacker's table for extra damage and a lasting effect, a fumble on the fumbler's; action dice such as a giant's d24 or a second action's d16 scale the crit range to the die; a spell check's total says what the spell does, with spells lost on a failure or a god's patience wearing thin; Luck is burned the more readily the more is at stake, and some spend it for friends.
- **Reactions** each take the round's reaction when worth what they cost: Shield turns a hit into a miss, Uncanny Dodge halves a blow, Parry, Shield Block and Deflect Attacks take damage off, Nimble Dodge adds to AC as the attack comes, Hellish Rebuke burns whoever hurt it, Riposte strikes back at a melee miss, and counterspells go by the spell's level, a check, or the caster's save. Any reaction's harm, what it lays, a buff, healing, a recharge or a strike is weighed the same way at every moment: what it does to the one who set it off (by its save's odds), or for itself, against what it costs.
- **Summons** (Spiritual Weapon, Conjure Animals, Summon Animal) are worth calling when they'd do more over the fight than the summoner's own blows. They go when their time runs out, the summoner's concentration breaks, or it stops sustaining them (PF2e). Something that isn't a creature (a spiritual weapon) can't be attacked and doesn't hold the field alone. The story tells what they did.
- **Legendary actions** come between other creatures' turns, from a pool that comes back at the start of the creature's own turn, each the best blow it can strike from where it stands. Legendary Resistance turns a failed save that would take it out of the fight (a hold, a stun, a killing blast) into a success while it lasts.
- **Regeneration** stops for a turn after the damage that stops it (a troll's acid or fire). While it works the creature can't be killed: cut down, it lies there mending and gets back up, so the fight isn't over, and anyone with fire or acid goes to finish it. At 0 with its regeneration stopped, it dies if 0 is death for it. Undead Fortitude keeps a creature at 1 hit point on a save.
- **Saves:** Magic Resistance gives advantage against spells and other magic; a friend's aura (Aura of Protection) counts the best one within reach while its bearer is up; 5e evasion takes nothing from a save for half on a success, half on a failure. Situational bonuses (against magic, fear, poison) count only against what carries those tags, the best of each kind. A foe's aura (a frightful presence, a stench) makes a creature save as it comes inside or starts its turn there, and thinking creatures count that cost before walking in to strike.
- **Size:** a creature can shove or trip one up to one size larger.
- **Crowd control** is valued by the damage it prevents. The system's tags decide immunity (mental, fear, sleep and others), and some systems let strong targets resist better (PF2e incapacitation). Feral casters cast at random, or whatever does the most right now.
- **Healing:** a heal that leaves the main action free (a bonus action) is preferred. Anyone down is back up with any heal, so for them the cheapest way wins.
- **Opportunity attacks:** walking out of a foe's reach gives it one melee attack, its reaction for the round. Tactical and Mastermind characters keep fighting the foe beside them, and when they must leave (to heal, to flee) get clear safely first if the turn still allows what they're leaving for. A character whose player ticked "Roleplaying is very important to me" forgets as often as **Roleplayers forget opportunity attacks (%)** says (default 33). A way out that doesn't cost the main action (5e Nimble Escape, Cunning Action) is second nature to anything that isn't feral.
- **Walls:** the shortest way round comes from a quick grid search over the fighters' part of the map (`foundry/pathing.js`). With no way round, crossing a wall counts as four times difficult terrain for that square, and a creature that can't manage that in one move gives up on going that way.

### Health callouts

`story/health.js`: after harm that leaves a creature up and looking worse than before, the story says how it looks, in the same beat (Roleplay: an `event.healthState` line; Standard: a row, `Story.Labels.Health`; the Statistician: `Log.HealthState`).
- **Data:** a harm event carries `hpBefore`, `hpAfter` and `maxHp` where the harm left the one it hurt lower and above 0 (`simulator.js` `noteHp`, through `dealDamage`'s `entry`; in a player's turn, its last blow at each creature, from the sheets: `live.js` `harmedAsShown`). Its subject is `targetId`, else `actorId`.
- **When:** how it looks after the harm differs from how it looked before. So a state is told once, and again once it's healed out of it and falls back in; never at 0 (the fall is told). Each callout comes from its own event, so a live battle's log told again says the same, and a Rewind takes its callouts with its turns.
- **The core's bands** (`FASTFIGHTING.Health`): below 50% annoyed, 25% wounded, 10% bloodied, 2.5% nearly dead.
- **The options hook:** `buildStory`'s and `storyBeats`' `healthState(unitId, fraction)` returns a label, `{label, hidden}`, or null (nothing to say); left out, or failing, the core's bands. `foundry/health-estimate.js` `healthLookup({tokenOf, playersKnow})` builds it for the live battle and the planner. With the Health Estimate module on (`healthEstimate`, its API `game.healthEstimate`), its `getStage(token, fraction).estimate.label` from 43.7% down (`HE_THRESHOLD`), hidden where `hideEstimate(token)` says so or the token is hidden; else the core's bands, hidden where the players can't tell how it is (`live-battle.js` `playersCanTell`: one of theirs, or one a player's character perceives, unless it's hidden and not yet given away). Any failure falls back to the core's bands.
- **Hidden:** told openly (`storyBeats`' `open`), a hidden callout goes to the GMs' part (`gmHtml`); whispered, it's told with the rest.

## Temporary migrations

Code that keeps old data working for a few releases has a test in `tests/temporary/` that fails once the core's
version reaches the release it goes with (its `REMOVE_AT`), the test's header listing everything to remove, so it's
never forgotten. None at the moment: 0.7.0 removed the last (Speed Runner as DPS, the old single store of live battles,
and surprise as plans said it before 0.4.0).

## Development

- Junction or symlink this folder into Foundry's data folder as `Data/modules/fast-fighting`.
- `npm install`, then `npm test` (Vitest) for the engine, story and parser tests. `npm run test:reworded` runs them again with every word in the language files reworded, so the tests never depend on the wording. GitHub runs both on every push to `main` and every pull request.
- **Words:** every word a GM or player reads is in `languages/en.json` or `story/en.json`. The code names keys and never holds the English; the tests read the words from those files and check every listed language for unknown keys and matching placeholders.
- **Reviewing system updates:** `tools/review/` (dev only, never in the zip) is what every helper's review check shares, so a game system's update never means reviewing every item: fingerprints (`fingerprint.mjs`), the names a script uses and links to them (`names.mjs`), the ledger and snapshot files with one entry per line (`ledger.mjs`), comparing a fresh scan with them (`compare.mjs`), and the report and the GitHub issue's body (`report.mjs`); `tests/review-tools.test.js` tests them. A helper adds a small part of its own: reading its system's packs, and which of its items its code names (FastFighting PF2e's `tools/review.mjs`, `review/` and system-watch workflow).
- **Releasing:** push a `vX.Y.Z` tag. The release workflow runs `npm test` in a job with read-only rights; then a job that may write (`contents: write`, and nothing from npm) sets the version and download URL in `module.json`, and builds `module.zip` (`module.json`, `scripts`, `styles`, `languages`, `keywords`, `story`, `templates`, `README.md` and `LICENSE`).
